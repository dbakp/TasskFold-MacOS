# Keep all-work and active-work reads independent

A cold project query asks TaskCache for all productive work; planner/grouping and navigation counts ask for productive work excluding archived projects. The former single cache slot evicted the other reading on every alternation. With any archived project, moving through uncached projects could repeatedly walk and project the full hierarchy. The iOS native filtered list delegates to Store.matching, while grouping and the calendar/planner use Store.productiveReading; both independently owned Stores share this Core behavior.

TaskCache now retains the all-work reading and one reading for a nonempty exclusion mask. A new nonempty mask replaces only the latter. Actual task-source changes clear both; identical updates keep them. No visibility or permission decision is cached differently, no action authority is added, and query keys, task order, project indexes and existing Store access gates remain unchanged. Memory is bounded to one additional workload reading, not one per project, query, account or historical mask. Both slots remain owned by the existing source-bound TaskCache.

The explicit same-host Debug measurement traverses 24 distinct project queries interleaved with the active-work read over 1,600 synthetic tasks in 32 projects. Three-run medians improve from 467.09 to 21.66 ms in the iOS owner, and 496.24 to 21.98 ms in Mac. Each final ordered task-ID list equals its own baseline and an independent filtered source oracle. Active work/presentation/outline equal fresh direct readings after every project. The test does not impose a timing threshold. This is aggregate query preparation, not per-tap latency, optimized-release speed, physical FPS or drag/rendering acceptance.

The iOS owner independently passes 216 focused checks (217 selected); Mac passes 215 (216 selected). Each has one intentional skip of the earlier timed-date benchmark. New deterministic cases cover alternating masks without recomputation, bounded mask replacement, heading/legacy/unavailable context, task edits, completion/moves, identical updates, cleared/replaced workspace inputs, retained snapshot immutability and exact source preservation. Existing hierarchy, filters/assignment, planner, organization and navigation-count coverage passes.
