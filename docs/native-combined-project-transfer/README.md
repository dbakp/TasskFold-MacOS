# Native combined file and recording transfers · 6 November 2026

The transfer screen now creates file preparation through one Store factory, with the same account/origin/workspace/session and recovery-availability fence as transfer recovery. The reserved integration invokes that actual factory, private Keychain-backed preparation journal, production Backend and Store against genuine disposable Auth, REST, complete owning schema, Storage and production handlers over scoped validated TLS. The DEBUG bridge maps only the explicitly enabled project-files/task-files routes to that owned TLS handler; normal networking, trust, release code, migrations and rollout flags are unchanged.

The `--project-transfer-combined` scenario combines one original file referenced in both a task and its inline discussion with published, in-flight and removed recordings. The app prepares one private copy, reviews the exact file consent and three recording counts, then preserves the original command and preparation across offline send and cold processes. The server commits while withholding an old-audience download; the response is lost. Original recovery proceeds with fresh file/recording transfers paused. The app refreshes the team boundary, verifies the actual copied file bytes through Backend, and clears the preparation only after confirmed transfer. A final offline cold process checks both journals and saved workspace.

Reproduce after building the current own signed isolated host, using Node 22 or later:

```
node Scripts/Database/test-native-audio-publication.mjs ios /tmp/taskfold-new-native-combined.json --keychain --project-transfer-combined
```

The original published-only and mixed-recording-only modes remain available. Each repository owns its implementation.
