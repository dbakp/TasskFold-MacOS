# Reversible original restoration — service candidate

Reviewed 7 November 2026. This batch adds a disabled, independently owned service for restoring the **subtask structure** retained before an explicit repair. It does not restore an entire task or workspace, replace newer notes, or enable restoration in the shipping apps. The existing saved/current comparison is read-only and cannot authorize this write.

A fresh restoration review binds the account, task generation, project/workspace, exact original and current source digest. Applying it retains the current source, records, projection and authoring authority as a separate inverse copy. An older malformed tree is displayed without re-projecting it over the retained records. Ordinary subtask edits and realm moves are refused until Undo. Unrelated current root notes and priority remain current.

Undo and Redo require a fresh review of the latest phase and revision. Every boundary rotates record incarnations and increases revisions, so pre-cycle editing requests cannot become valid again. Later subtask work refuses stale Redo. Actor-bound immutable receipts support check, retry and stop without applying a second change. Reversals can remain available while new restorations are paused. Public wrappers are invoker-only, recheck current caller task/history access, and give no direct private-table grants.

Current typed attachment references require the existing exact file inventory. A retained manifest pins actual private Storage objects and task bindings, rather than treating a JSON reference as proof that bytes exist. Reversals validate the stored manifest even when the older malformed tree does not reference a current attachment. Unresolved typed custody refuses review. No file is copied or new read grant created. Retained inverse payloads share the original-storage quota.
