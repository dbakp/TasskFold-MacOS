# Reviewed filter assistance — 5 November 2026

## Implemented

Both filter editors offer **Suggest a filter**. The optional Apple on-device model receives only the entered description and fixed grammar instructions: no tasks, existing query, directory, names/IDs from a catalog, credentials or backend data. The structured response contains one expression string. Cloud assistance remains disabled. Both assistants now share the same on-device availability/locale check; system settings and deployment gates are unchanged.

The expression remains editable. **Check preview** uses the ordinary FilterParser/FilterRule validation and actual task matching, with a deterministic meaning caption and match count. No model-written rationale is trusted. Query preparation and reference revalidation run in cancellable background work, with an exact snapshot fence after awaiting. Stop, Cancel, changed descriptions/queries, superseded work and source/workspace/session changes discard late results. Content is hidden and the sheet closes when the filter source becomes unavailable.

**Use expression** updates only the existing editor draft; the user still chooses **Save**. Name, sort, completion visibility, grouping, unknown fields and tasks are not replaced by model data. Unsupported saved query versions keep their existing refusal. Exact source snapshots include the original filter record, current saved copy, editing mode, expression and condition identities. SavedViewEditor now also captures its opening workspace and session before any save.

The parsed proposal binds exact target identities, names, project/section ancestry, person/project scope, pattern matches, availability/sharing classifications and relevant date preferences. It revalidates before Use and again at Save; a replaced/renamed/deleted/ambiguous target, changed wildcard or subproject set, changed section/person scope or changed date settings requires a new preview. Editing the expression explicitly returns to the ordinary manual-editor path. Relative dates intentionally stay relative; a preview is not a frozen list of task IDs.

Project-member reads are demand-driven within the helper. A typed lookup hint or a directory-dependent predicate triggers the existing account/access-revision-bound member RPC, once for the current project list per helper foreground session. Missing or ambiguous names and known exact email/ID targets get a complete current directory check before acceptance; fallback display names do not invalidate real email/ID identities. Basic date/priority/Inbox queries and reserved person selectors need no helper directory read. Opening the helper alone does not start member reads. The normal editor skips redundant directory warming for an applied reviewed proposal; explicit subsequent manual editing resumes its existing behavior. Failed/cancelled reads leave the saved filter unchanged. No endpoint, grant, policy, schema, credential or hosted service changed. [Cleanup](cleanup.json) and [Core cache measurements](core-cache-storage.json) keep each of the four selected compiler caches within 768 MiB. No Simulator was booted.
