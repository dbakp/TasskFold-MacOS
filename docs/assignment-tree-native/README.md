# Native project changes preserve source data

1 November 2026. Two real native-control flows now pass on iPhone, iPad and Mac, with independent verification of the actual persisted snapshots. Mobile uses dark appearance and explicitly requested standard text. All data is synthetic in the reserved isolated host. The Mac and mobile test source, matching isolated host source, current app binaries and strict app/runner signatures are recorded in verification.json. Each repository owns its verifier and retained fixtures; mobile evidence originates in TaskFold-iOS, irrespective of which repository contains the copy.

## Accepted local flows

- Open the ordinary task editor/inspector, choose another project with the native picker, save (mobile) or autosave (Mac), then quit/relaunch. The complete root has only the expected project, section and assignment changes. Nested children, legacy text, both distinct Unicode keys and the exact large integer remain intact.
- Try the same project change with an unsupported child container. The native picker retains its original project and shows the complete review message. The immediate saved file is byte-for-byte unchanged. Cancel/quit and cold return retain the complete snapshot values.

Each accepted destination retains its original, saved/refused and cold-return JSON snapshots, native screenshots, XCTest summary and lossless verification report. JSON object order can change between processes, so cold snapshots are compared independently without rounding numbers or normalizing Unicode keys; original opaque tokens are also required. The first phone attempt failed only its final strict whole-file cold-return assertions. Its two supported snapshots have exactly equal values and different key ordering; the concise failed-attempt evidence is retained rather than counted as a pass.

## Reproduce verification

Run `python3 Scripts/verify_assignment_native.py docs/assignment-tree-native/phone/attachments docs/assignment-tree-native/phone/test-summary.json /tmp/taskfold-assignment-phone-verification.json`, then the equivalent ipad paths. Run `python3 Scripts/test_assignment_native_verifier.py` for eight checks against real retained fixtures, including numeric rounding, Unicode-key loss, Boolean/number changes, modified refused work, failed/skipped native results, foreign-device evidence and unsafe attachment paths.

The Mac inspector now automatically brings each project-change refusal into view, including repeated failures. The final native check requires the whole message to fit inside the inspector viewport, and its screenshot is retained. Earlier Mac setup/query attempts and the data-only pass before this visibility correction are recorded separately. The guarded DEBUG Mac app seeds its own synthetic data because the sandboxed runner cannot write that app’s cache.
