# Direct discard of an expired audio review — 28 October 2026

An editor whose prepared Save was removed or changed can now choose **Discard this review** directly from Close. The separate-copy action remains available. The dialog explains that other saved recordings and pending Saves stay on the device. This resolves the need to attempt an unnecessary copy before leaving, including when the app's payload-entry quota is occupied.

The storage operation validates the raw owner and original saving authorization under the same nonblocking file lock. It refuses if that exact authorization is still prepared/discarding, or its exact draft is already saved. It rotates and synchronizes the existing fixed-size departure nonce, then removes only matching review ID/revision/target references not claimed by another pending Save or its origin. Changed review revisions, changed authorizations, primary drafts, private publications and other accounts remain separate. No new audio payload or journal is admitted, and no growing tombstone log or new disk format is introduced.

The controller exposes Discard only for an eligible review. It retires the exact retained authorization and closes only after storage acknowledges the operation. A busy lock or uncertain acknowledgement keeps the review in memory, allows explicit retry, and cannot falsely report that Quit is safe. The original store remains authoritative if the workspace changes during the request. Real filesystem exhaustion, power loss, forced termination and every account interleaving are not established by the controlled fault cases below.
