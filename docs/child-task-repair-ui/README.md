Ordinary use remains **disabled**. This is a bounded part of the broader older-subtask migration checkpoint, which remains **To build**.

## Implemented

- Each app owns its repair screen, read-only positional outline, Store integration, account cleanup and native acceptance fixtures independently.
- Account exposes saved repairs even when new repairs are disabled. New repair review requires the explicit repair gate and the existing adoption/child gates. No ordinary Info.plist gate was enabled.
- Fresh scoped reads show the original structure and explicit choices to repair references, preserve legacy values as tasks, repair list shapes and move items. Each choice obtains a server preview; whole-tree identity and snapshot changes invalidate Save. A bounded outline refuses the entire oversized structure rather than presenting partial editable data.
- Original payloads remain opaque bytes. Display labels are bounded; no floating-point conversion of unknown original values occurs in the production outline. Preview choices remain ephemeral until Save; dismissing unsaved choices requires confirmation. Partial review choices are not a durable draft.
- Save uses the independent encrypted repair journal and the original request identity. Admission checks readable local storage, pending commands and hierarchy drafts, open editors and preserved private edits. Pending adoption and repair requests block one another for the same root. Account removal and synthetic fixture reset include repair state.
- Saved requests offer Check, Retry and Check and stop. Applied requests retain their confirmation and separately authorized original export. Background/account transitions hide sensitive reviews and cancel their model leases; returning requires fresh review.
- Multiple actions in a list row use independent button behavior. Review content remains visible while a proposal is checked; original retrieval has a visible busy state and cannot race dismissal.
