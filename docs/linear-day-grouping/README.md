# One-pass Today and Upcoming grouping · 7 November 2026

Today and Upcoming previously resolved displayed task dates again while selecting overdue work, collecting future dates and filtering every day section. A fourteen-day list therefore repeated fixed-time parsing across the same rows. Both independently owned apps now create one current `TaskDayGroupsRead`: resolve each supplied row once, retain per-day row order and the original global overdue order, then apply each platform's existing manual/priority ordering. iPhone's selected-calendar path reads its already-filtered rows directly. Mac's unrelated non-dated overdue handling stays unchanged.

Every current row and identity is retained, including headings, independent children and duplicate source IDs. Completed overdue rows remain excluded from Overdue; completed current/future rows retain the caller's visibility policy. Empty horizon days, later work, floating dates and the existing unsupported-date fallbacks remain the same. The read is a local value projection, refreshed from current filtered work/calendar/clock; it adds no persistent or cross-account cache and changes no task/order/preference writer.

Each owner passes 32 focused Core tests, including nine new grouping cases. They compare the prior section algorithm with the new read across mixed completion/date states, original overdue and duplicate-ID order, empty/far horizons, travel/DST/display calendars, unsupported fixed fields, heading/child metadata, fresh source/clock/zone reads, existing manual priority order and a timed workload. Debug (-Onone) grouping for 120 timed rows across 14 dates falls from about 0.59–0.60 seconds to 0.031 seconds. These are derived grouping measurements, not total render time, optimized-release or physical-FPS evidence.

The current signed iPhone Simulator passes the existing production-list journey: a real long-press drag from Overdue into Today, saved date/row verification, actual history Undo preserving task fields, and four Today/Upcoming navigation switches. The saved result and screenshot are retained; this four-row journey does not establish large-library smoothness. The reused Mac host initially lacked its license resource and backend configuration. The license was restored byte-for-byte from its owner, and compile-only configuration uses a blocked loopback URL with no credentials. The full resource inventory was checked before the successful build; the app was not launched. Initial logs and the repair receipt are retained. The isolated Mac Debug app builds and signs from its own current sources; native Mac interaction remains unavailable while computer control reports locked. Whole-list eager layout, pointer-target scans, wider account/window/accessibility and physical smoothness remain open.

Installed Mac31 and the verified Release Mac33 archive remain intact. Mac33 does not include this later grouping source change; the next normal release build must include it before installation. Phone installation stays deferred. No hosted service, schema, ordinary rollout gate, normal app session, system permission or real task data changed.

Reproduce: `bash Scripts/test_core.sh --filter 'TaskDayGroupsReadTests|TaskRowPlanningReadTests|PlannerTests'`. Native case: `WorkflowSourceSelectionUITests.testActualDayDropUndoAndNavigationResponse` in the existing reserved signed host.
