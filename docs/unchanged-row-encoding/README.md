# Prepared unchanged rows during local saves

Large plain workspaces prepare immutable row encodings away from the interface thread. A subsequent save reuses only rows with the same authored source at the same table/offset and encodes every changed row. IDs alone never admit a cache hit. Preparation is bounded to one worker and one replaceable pending request, with byte/workspace/account/session/access/revision fences before adoption. Small, unsupported, opaque and over-budget workspaces retain the existing writers. The cache is private memory; it adds no wire fields or deployment dependency between owners.

Files are still read on each save, and atomic protected writes, current mutation admission, recovery staging and Undo remain synchronous. Metadata validation may be reused only for identical canonical encoded metadata bytes. Changed private ledgers take the existing decoder checks. Metadata splicing locates the actual tables member in trusted encoder output; raw documents continue through full syntax validation. Structural plain-row depth checks avoid rescanning large strings; the whole-envelope Foundation depth boundary is retained through conservative fallback.

The first actual iPhone Simulator baseline used 2,004 tasks and a 2.88 MB plain reference. Warm/cold release-to-commit cost was about126/130ms, including80/85ms encoding and2–4ms atomic write. An intermediate implementation reduced encoding but barely changed the total; it is retained as rejected performance evidence, not an accepted broad responsiveness claim. Final current-source results are recorded separately.

Core checks cover missing/duplicate IDs, reordering/membership/table names, reconstructed records, exact Unicode/numbers/opaque fallback, changed metadata/private-ledger rejection, stale/cancelled preparation, external same-size replacement, failed writes, budgets and depth boundaries. Performance diagnostics compare the same codec with/without prepared rows and identical metadata policy; these are Debug CPU measurements, not physical FPS or broad smoothness acceptance. iPhone installation stays deferred and wider drag/navigation performance remains open.
