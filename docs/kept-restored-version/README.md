# Keep a restored older subtask version editable

The atomic save is implemented in the service and client data contract. It requires the fresh owner/current-workspace-admin comparison, explicit task-copy format/history choices, and the exact restoration actor/ID/revision/digest. Both the database `archive_restore_adoption_enabled` switch and the app's `TaskfoldChildOriginalAdoptionEnabled` switch default off. No native control calls this action yet.

The save retains the entire newer inverse and all pre-save copies/history in an independently owned immutable archive before staging any edit. It validates and pins the union of retained/current files under that archive before releasing the old inverse and its pins. The actual task update still runs under caller RLS and the existing exact mapping proof; no caller-settable exemption or ordinary hidden-copy read is added. Only after the mapped mirror, history, access and receipt are confirmed does the restoration become `adopted`. A deferred constraint prevents committing a staged archive/receipt without the complete transition, including versions with no files.

The original restore receipts remain immutable. Exact repair nonce/fingerprint Check, retry and Stop remain available, including after the adoption switch is paused or role is lost. Content export of an adoption archive additionally requires current custody. Ordinary repair behavior and existing archive layouts remain unchanged when there is no restoration binding. Budgets credit only the exact inverse transferred into the new archive, with actor and workspace accounting kept separate. Removing that archive through the existing explicit retention operation releases only its pins; live tasks and file bytes are not removed.

Client commands and partial history drafts preserve the binding across cold serialization and edits. Original export accepts a null authoring preimage only for this explicit bound adoption, and requires its matching retained context. Payloads remain opaque raw bytes, including large numbers and distinct Unicode keys; they never pass through a floating-point dictionary. Existing model recovery and bounded response contracts are reused.
