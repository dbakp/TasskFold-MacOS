# Assigned-name filters

Implemented independently in the iOS and Mac repositories on 8 October 2026. [Todoist’s official filter reference](https://www.todoist.com/help/todoist/features/introduction-to-filters-V98wIH), checked today and dated 4 September 2026, documents `assigned to: m* smith` for wildcard collaborator names. Taskfold now supports that productive query while retaining its existing exact-person behavior.

## User behavior and contract

- The native builder offers **Assigned name matches** under People and status. Enter `M* Smith` to show tasks assigned to matching current collaborators. The builder starts with `*`, as the other name-pattern conditions do. The editor previews the result count and rejects empty, oversized or invalid escaped patterns before Save.
- Unquoted `assigned to: M* Smith` and `assignee:M* Smith` select the dynamic version-1 predicate `assignee_name`. Explicit `assignee matching:"M* Smith"` works with quoted spaces and protected operators. Canonical expressions use that explicit form.
- `*` matches any number of characters, including none. Matching covers the whole display name with invariant case/accent folding, bounded dynamic programming and the existing 120-scalar pattern/400-scalar name limits. Escaping `\*` selects a literal star in the explicit matching form; `\\` selects a literal backslash.
- Exact display names and emails retain their existing stable ID resolution. `assigned to:"M* Smith"` treats the quoted star literally and resolves one exact person. Ambiguous exact names still require an email or ID. Wildcards intentionally allow several people and follow current names/memberships; they do not change task assignments.
- Wildcards match available display names, not emails or synthetic names such as Project owner. Accepted membership/profile records supply names; pending invitations and fallback-only names are excluded. A known current user can match their actual profile name when available in a project’s directory.
- Assigned tasks without an available display name or valid membership in their accessible project stay excluded through NOT and OR. Signed-out readers fail closed. Unassigned tasks can match exclusion queries. Independent comma-separated queries retain independent scopes: `assigned to:M*, all` can still show tasks through its explicit All section.
- App lists, editor counts, ordered query groups and widget ID projections receive the same scoped current directory. Renames and membership changes participate in query cache identity. A name match must belong to the task’s own project directory; a differently cached name in another project cannot make it match. A pattern never invents a capture destination or default assignee.
- The widget projection contains only its existing names, bounded task IDs and time-zone/expiry metadata. No collaborator directory, profile fields or query AST is added to widget data. This is projection/model evidence; installed WidgetKit host acceptance is separate.
- Offline queue/export/restore preserves the pattern string. Exact account IDs retain the existing restore remapping behavior. Unsupported query fields remain preserved and non-editable by current readers; older shipped clients still require the joint rollout acceptance already recorded in the P0 plan. This change adds no backend column or migration.
