# Assignment clearing without checklist loss

1 November 2026. Both independently owned clients now clear project-incompatible assignments through a bounded full-source transform. Known ASCII assignment fields are changed without flattening preserved objects, exact Unicode metadata or legacy text rows. Sparse/null child containers remain sparse/null. Unsupported child containers, depth or aggregate budgets refuse before any draft, selection or queued mutation is published.

Project pickers and checked quick-entry writes compute a complete new draft before replacing the current one. Failed project changes retain the input and expose a wrapping inline error plus an accessibility announcement. Read-only reminder/assignee previews avoid rebuilding a checklist on each keystroke. Mac multi-selection, queue normalization/projection, backup baselines and the isolated shared-move peer use the same guarded transform.

Assignment-only draft cleanup is omitted from personal move requests, including its obsolete checklist baseline. The comparison uses the editor's original baseline, so newer child notes remain current. Genuine additional child edits remain authored edits with their original conflict baseline. This preserves the existing metadata-only server move contract; it introduces no server change.
