## Scope decisions

- The original P0 foundations are migration, useful capture, a documented filter subset, independent deadline/estimate planning, reminder reliability, recovery and safe device continuity. The requested productive widgets remain in scope even though the original Todoist parity table placed widgets in P1.
- Full Todoist query-language equivalence, additional date grammar, subprojects/archive/templates, external Google/Outlook mirroring, goals/Karma, advanced teams, location/urgent alerts and wearables retain their original later-phase priority. They are a port backlog, not newly discovered P0 blockers.
- Ordinary iPhone/iPad application acceptance uses Xcode Simulators as requested. Physical delivery/distribution has separate prerequisites; do not turn physical-device combinations into prerequisites for already accepted ordinary app journeys.
- Todoist source data must remain unchanged. Use isolated synthetic fixtures, preserve unrelated work, close test sessions when no longer needed, and prune inactive build/export duplicates while retaining useful evidence.
