# Dated reads survive metadata-only refreshes

Every snapshot assignment used to clear dated groups, even when the task rows had not changed. The Store now keeps a dated presentation revision tied to authored task values and project/access presentation. An identical decoded refresh or unrelated preference update can reuse the current rows. Snapshot observation remains active, so relevant view settings still reach SwiftUI. Query options, day/zone/calendar and privacy/session/workspace/origin boundaries remain part of the read. Deferred edits retain conservative invalidation.

Saved and explicit filters keep a separate full snapshot fence in the bounded key. Their rules and metadata can change without changing task rows; the actual Store test changes a saved AST and confirms new matches. Current title/date edits, project-only archiving, unreadable/return, clock changes and observer notifications also pass. Neither the read cache nor its revision grants edit authority; action/review bindings continue using their current full source. Both independently owned apps implement this change; the Mac assigned-only direct-read path is unchanged.

The fixed iPad workload has 2,004 tasks, 500 distinct timed schedules and a large opaque reference. The optimized read rebuilds zero groups and takes 0.75 ms in total. Per preference-only event, measured grouping falls from 82.1 ms to 0.019 ms. Encoding/decoding the complete synthetic snapshot still takes about 531 ms per decoded event and is reported separately; these figures do not establish whole-app navigation or physical FPS.
