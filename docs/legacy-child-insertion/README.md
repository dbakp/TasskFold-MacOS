# Preserve saved children during nested insertion

Reviewed 7 November 2026. Adding beneath an older parent previously projected its unsupported checklist through an empty list, replacing the saved object/text/number/bool with the new child. Repeated parent identities could also receive the same inserted child in multiple branches.

The independently owned clients now require one nonempty, named, ordinary parent identity and a missing/null/array child container. A scan cut short by the readable depth bound refuses insertion rather than declaring an identity unique. Refusal returns a review message before generating or inserting a child. Existing top-level additions and valid nested additions retain their behavior; existing children, parent metadata and unrelated opaque/text siblings remain intact.

Each owner passes 65 focused Core tests with two explicit integration skips across 67 selected cases. Four new regressions cover unsupported containers before/after cold decode, duplicate/unnamed/opaque parents, an incomplete identity scan, and successful additions with missing/null/empty/populated child arrays. Byte comparisons sort ordinary dictionary keys while retaining opaque original bytes. The Mac baseline reproduces 11 failed assertions before the fix. Its first fixed run exposed six nondeterministic test-encoder ordering assertions; the final test writer corrects that comparison, and both final suites pass. Exact sources and logs are recorded in verification.json.

This is a bounded preservation fix, not completion of the older-work migration. No schema, hosted service, rollout gate, real task or installed app changed. Genuine service transport and actual model inference were deliberately not started. No new full app build or native save/keyboard/speech claim is made; this code will enter the next signed update. Prepared Mac35/phone43 predate it. Installed Mac31 remains untouched because computer control still reports locked after the user's unlock response; phone installation remains deferred. Wider mapping, editable-cache, identity/lifecycle and file/discussion custody work remain open. Curated checkpoint and scoped substep totals do not change.
