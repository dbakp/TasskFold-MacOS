# Assignment filters

Both independent native apps support `assigned` (any nonempty task assignment), `!assigned` (unassigned), `assignee:others` / `assigned to:others` (assigned to someone other than the current viewer), and exact collaborator name/email references such as `assigned to:"Alex Smith"`. Existing `assignee:me`, `assignee:unassigned` and collaborator UUIDs retain their meanings. Others excludes unassigned tasks; its negation includes your assignments and unassigned tasks. Missing viewer identity excludes Me/Others queries even under NOT/OR.

The builder exposes Assigned tasks and adds Others in its Assigned to picker. All 45 existing/current conditions remain available once each, grouped into nine shorter menus. People and status contains only Assigned tasks, Assigned to and Completion; the selected value remains visible on the condition control with a minimum 44-point target. At accessibility text sizes, a navigated chooser uses scrollable grouped lists with wrapping labels, selected checkmarks and a Cancel action. Normal text uses short native menus in a fixed order. This replaces the long scrolling condition menu in both native apps. Expression editing resolves full names/emails from the current available accepted project-member catalog. Names compare case-insensitively; duplicate copies of the same identity across projects are deduplicated. Ambiguous names reject Save and require an exact email or ID. Pending invitations never enter the Store member catalog. Quoting protects operator words within names. The editor refreshes members when expression mode or assignment conditions are active; an unavailable directory leaves a validation error and existing offline member caches remain usable.

Named references save as the selected stable collaborator UUID, or Me for the current user. They follow that identity through renames and do not retarget by a later reused name. Existing UUID documents remain readable without a directory; the builder displays an unavailable collaborator when absent. This query is a selection over task assignment fields, not proof of current recipient membership or permission to assign. Normal task RLS and editor assignment checks still apply. This does not add assigned-by metadata, dynamic person-name patterns, shared/personal project scope or hierarchy.

The version-1 AST adds empty-valued `assigned` and the `others` assignee value. Older readers without these capabilities must preserve unsupported documents and disable editing rather than substitute a default. The minimum preservation baselines remain iOS `c8d96f8` and Mac `362b3ad`; both devices need the new assignment implementation to evaluate/edit these documents. No backend schema or policy changes are needed. Typed aliases are not stored as mutable names.

Account-cache and mutation-queue encoding preserve the complete AST. Cross-account backup keeps Assigned/Others relative to the destination viewer and changes a source-account UUID selection to Me. No assignment predicate invents a capture recipient. Widgets evaluate the same persisted UUID/state rules for eight civil days and export only matching task IDs; collaborator emails/identities and the query AST are not added to the private widget payload.

Verification: each own Core suite passes 512 tests, four existing optional integration skips, zero failures. Cases cover assignment states, missing identity under NOT/OR, duplicate names, exact emails, pending member exclusion, ID preservation with missing directory, parsing/serialization, offline queue, widget privacy/membership and backup semantics. Each independently owned actual-role database fixture passes and rolls back to zero fixture users/views. SQL JWT claims simulate authorization context; this does not prove native sign-in or paired HTTP transport. Own unsigned Release app/widget and Debug UI-test-target compilation pass; Mac Release contains both x86_64 and arm64. Source captures and independently owned input hashes are recorded in `assignment-evidence.json`. Ten final isolated iOS Simulator flows pass (five on iPhone and five on iPad), covering light and dark Accessibility XXXL assignment/name-pattern flows and the light keyword regression, including relaunch persistence. Fourteen unmodified final assignment captures are inspected and independently retained in `docs/assignments/final/`. Largest text uses ordinary scrolling and partial viewports; long list titles can truncate. These are scoped interaction/capture checks, not Mac GUI or full VoiceOver acceptance.

Real paired native online/offline/member-revocation/restore, Mac GUI runtime, physical/provisioned widgets, VoiceOver/full-surface acceptance, remaining query grammar and full P0 acceptance remain open. The Mac runtime remains prohibited by the standing user constraint. No provider rollout or public release is activated.

[Todoist filter documentation](https://www.todoist.com/help/todoist/features/introduction-to-filters-V98wIH), checked 7 October 2026, documents Assigned, Others and exact collaborator names/emails. Taskfold's identity persistence and supported grammar above are its explicit contract.

The standard-size category menus use [Apple’s fixed menu ordering](https://developer.apple.com/documentation/swiftui/menuorder/fixed). The large-text chooser uses ordinary list scrolling rather than a clipped nested popup.
