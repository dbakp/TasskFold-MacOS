# Workflow destination indexes — 28 October 2026

Fresh workflow collision validation previously built identity sets for every saved table. It now builds sets only for destination tables present in the run. Existing activity, comments, private recovery and unknown future tables cannot collide with a row inserted into another table. Identity equality, case-folded task namespaces, run admission, row append validation and consumed-command protection remain unchanged. This is a cost reduction, not a new editing rule or a database migration. Both apps own their implementation.

Three new Core cases run against the old implementation before editing and against the new implementation afterward. They compare 90 destination/populated-table/collision combinations and 33 malformed/aliased/scope combinations with the frozen old constructor; admitted rows are compared with ordinary snapshot application. A saved-workspace fixture retains 90,000 unrelated history/future rows and creates a project without modifying those rows. Existing suites also cover whole workflows, prepared projections, failure/fallback, Undo and body size. Each repo passes 97 distinct selected Core cases before and after, with no failures. Compressed complete logs and final source/binary bindings are retained here.
