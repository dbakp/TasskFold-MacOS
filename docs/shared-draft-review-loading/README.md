# Responsive shared-draft review

Opening Shared drafts now shows a loading state while group resolution, bounded file reading, decoding and receipt cleanup run away from the interface thread. Refresh remains available. The view owns one active read and only the newest pending request; leaving the screen invalidates both pending work and the old result. Unreadable data displays an error and Try again, rather than an empty success state. The loader rechecks account/workspace generation, session, access revision, server origin and durable receipts before publishing its result or count. Workspace/session/server changes close the old editor and start a fresh guarded request. Receipt or destination/access refreshes reload the list without discarding an open edit; unavailable workspace access still closes it.

The validated mailbox is copied under the existing lock and decoded after releasing it. Imported drafts are retired with one best-effort transaction instead of reopening and rewriting the entire mailbox once per handled draft. That transaction rereads current data, requires the exact published workspace to remain current and removes only exact drafts with exact durable imported receipts. New/other-account drafts and changed copies survive. Cancellation is checked before reading and cleanup; cleanup failure leaves receipts responsible for preventing duplicate creation. Unimported multiline notes and draft identities remain intact. File format and import/save/discard transaction checks are unchanged.

## Scope still open

This completes background review loading and opportunistic cleanup, in addition to the earlier background badge read. Startup publication, import/save/discard transactions and other disk writes retain their existing semantics; this does not remove the earlier macOS shared-app-data permission wait. Native Mac interaction, wider account/window/accessibility cases, large-library navigation, physical-device FPS and the broader migration remain separately tracked. Mac29 remains the installed build; frozen Mac29/phone41 predate this source. No ordinary rollout gate, hosted service, physical-phone installation or normal app data changed.

## Verification

Each owner passes 29 sharing Core tests: the earlier 22 capture/count checks plus seven review cases. New cases cover a held read with only the newest pending refresh, leaving a review while reads are held, error/retry, a real 64-draft mailbox larger than 5 MB decoded off the main thread with exact unimported text/bytes, receipt cleanup preserving another account and wrong receipt values, malformed input preservation, and cancellation before imported-draft retirement.

Signed current-source iPhone and iPad journeys use the ordinary Shared drafts screen and actual Store loader. Both refresh while a read is held, open exact three-line Unicode notes, retain an unsaved title edit across an unrelated receipt insertion and restoration, cancel without saving, hide rows on malformed data and recover with Try again. Complete saved-cache and mailbox bytes are unchanged. Their final screenshots were inspected. The tablet test hides its system keyboard before reaching the form's bottom Cancel action; this final test-only adjustment does not change app source, whose prepared-source fingerprint matches both accepted runs. The phone's accepted case is retained rather than repeating an unchanged product check.

The first native attempts used the wrong XCTest element kinds for a spinner and multiline TextField; identifier-based queries corrected those test assumptions. All fixture controls are DEBUG-only, exact-test-bundle/flag restricted and use a private synthetic mailbox. No real account or normal shared app-group data is used. Core reproduction: `bash Scripts/test_core.sh --filter 'SharedCapture(ReviewReader|CountReader)?Tests'`. Native case: `WorkflowSourceSelectionUITests.testSharedDraftReviewLoadsWithoutBlockingAndRetriesUnreadableMailbox`.

The final independent Mac app builds and passes strict signature verification. Native Mac interaction/speech and physical rendering are not claimed by that build result. See the source-bound reports and the retained final phone/tablet screenshots.
