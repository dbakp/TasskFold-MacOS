# Audio draft departure recovery — 28 October 2026

Reviewed audio and already-authorized local Saves now have a departure checkpoint. A new journal-only operation reuses the ordinary Save validation and immutable authorization, but does not create a draft, remove a review, publish audio or invent new IDs. Its acknowledgement and exact state-read fence synchronize the containing directory, including a retry after rename acknowledgement failure. Media/journal payload formats, limits, account isolation and ordinary explicit Finish remain unchanged. The existing private `.lock` file now holds at most one canonical 36-byte UUID nonce. A checkpoint captures this before its explicit Save, and Discard rotates and syncs it before deleting the journal/reviews. Missing, stale, corrupt or oversized metadata cannot authorize a new automatic journal. An exact existing journal may be retained; an existing-only request never becomes a fresh Save. No new growing receipt log or media-quota file is added. Older clients that ignore this protocol are not accepted; the user-deferred rollout safeguard remains open.

Each live capture has an instance identity independent of its presentation request. Departure stops playback, stops a recording when that path can safely wait, waits for decode/current local work, and preserves its original private store. A retained Save from a closed view or another workspace can write only its frozen authorization to its original account. Cancellation returns failure; it does not assert durability or discard the retained work. Normal Save/Discard remains explicit.

## Mac

Normal Quit consults the existing editor safeguard first, then waits for the audio checkpoint. A failed checkpoint refuses Quit and presents a native, caption-free recovery alert. Ready audio sheets let AppDelegate perform that check. While recording, decoding, loading or saving, the sheet keeps its original modal termination protection; users must finish/cancel that work before Mac Quit. The window policy is restored on detachment and is not applied to other sheets/windows.

AppKit normally prevents termination while a modal sheet is open, before consulting the delegate. This explained the first native attempt, where Quit worked only after closing the sheet. The scoped window bridge follows [Apple’s documented window policy](https://developer.apple.com/documentation/appkit/nswindow/preventsapplicationterminationwhenmodal), while the app’s asynchronous response follows [terminateLater](https://developer.apple.com/documentation/appkit/nsapplication/terminatereply/terminatelater). No sudden-termination or system security setting is changed.

The final signed Mac app passes a native CUA journey: Cmd-Q during recording leaves recording active; stopping produces the decoded synthetic clip; a pre-journal Save plus real separate storage lock produces an unknown outcome; Cmd-Q reaches the new alert and leaves the process alive. After keeping the app open, reopening the original workspace and releasing only that test lock, Cmd-Q exits without clicking Retry/Finish. A different process, launched without reset/fault flags, discovers one Finish saving action with the original raw caption and no saved-recording row. Explicit Finish produces one saved row and the same 0:01 caption; normal Quit exits again. The receipt binds the distinct process IDs and final sources/binaries. The final native accessibility tree was inspected; the prototype alert was also visually inspected inline. No persistent Mac screenshot or clean XCTest runtime result is claimed.

AppKit dismisses the sheet before invoking the delegate in this journey. The retained writer is therefore necessary even on refused Quit: the original authorization remains available after reopening Audio draft. The first modal-policy diagnostic and the earlier always-ready bridge are not final acceptance; final evidence uses the busy-state policy.

## iPhone and iPad

The review’s inactive/background path checkpoints locally; the app delegate stops playback synchronously on resignation and requests a bounded UIKit background allowance for outstanding recovery work. Expiration cancels the wait and releases the allowance. This is best effort under OS scheduling, not a guarantee after force-kill or before a recording is decoded/reviewed.

One current native test passes independently on iPhone 18 Pro and iPad Air 13-inch (M4) Simulator, with zero failures/skips/reported runtime warnings. It reproduces a failed recovery write and failed pre-journal Save under a real lock, releases storage, presses Home, waits for exactly one actual Save journal and verifies no draft was completed. It reads the journal’s exact UTF-8 caption, cold-launches, invokes the single Finish action, and compares saved ID/revision, audio bytes, target, descriptor and caption with that journal. Both retained screenshots were inspected; they show readable saved review controls and caption, with ordinary scrolling on the phone. This does not prove UIKit expiration, physical interruptions, real microphone/speaker routing or spoken acceptance.

## Still open

Ordinary audio entry points remain gated. Real microphone/speaker/permission/spoken acceptance stays deferred at the user’s request. Automatic Mac Quit while a recording/processing operation is busy, recovery UX after an expired prepared authorization, forced termination before review/checkpoint, orphan/corrupt stages, full window/removal/backup/export lifecycle, task integration, private server custody and genuine delivery remain open.
