# Keep frequently visited task queries warm

TaskCache previously dropped every cached result once a new query exceeded its 64-entry limit. Searches could therefore evict frequently revisited project and saved-filter results together. It now retains the same maximum of 64 results, updates recency on hits and evicts one least recently used result on admission. Hits use one dictionary lookup. Counter overflow clears the cache conservatively. Exact query normalization, task matching, order and source-change invalidation remain unchanged; this is read-only and provides no edit authority.

Each independently owned Core executes 103 selected cases: 101 pass, two optional benchmarks skip, zero fail. Five new cases cover repeated project/search churn, single-entry eviction and hit promotion, capacity and edits/clear, timestamp/text normalization and a sustained 2,004-task journey. Existing filters, workload and navigation counts remain covered. The actual old source computes 308 results in that journey; each new owner computes 164. The baseline and final stage timings remain about half a second. These single Debug samples are not paired/repeated timing or evidence of physical UI speed. Cache retention is accepted; sustained native navigation, child-heavy and full-save responsiveness remain open.

Mac 53 remains installed and usable; this source is not packaged into a normal update. Existing-group provisioning still awaits Xcode development account access. No unchanged signing retry, Simulator boot, hosted change, user-data mutation or rollout-gate change is made. Both reused Core caches remain within 768 MiB. Only completed temporary source copies are retired; current packages, rollback, tasks, backups, Keychain, shared SDKs and other projects stay intact.
