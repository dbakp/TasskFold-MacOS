## 5 October: import and planning foundations

- Applied additive `p0_planning_foundation`, `fixed_planning_instants`, and `restrict_legacy_email_lookup` migrations to the existing Taskfold Supabase project. Mirrored migration history into the web reference repository for reproducible dependencies. No user task data was changed by the integration tests; each fixture transaction rolls back.
- Replaced REST v2 with API v1 envelopes, all-page cursor reads, rate-limit/retry handling, exact comment counts, source-account identity and deterministic per-user source mappings. A single authenticated security-invoker RPC imports projects, sections, labels and task trees transactionally. Retrying skips mapped resources, preserves user edits and does not resurrect deleted mapped tasks. Older imports did not retain source IDs and can produce new copies; preview warns explicitly rather than guessing from titles.
- Native requests explicitly select JSON and allow a longer import timeout; the original web streaming contract remains the default for deployed older clients. New web code uses checked JSON completion and shows warnings before import. Source metadata preserves unsupported fields; attachments remain HTTPS links with an expiration warning. Completed history, archived projects, reminders, collaborators and filter rules are explicitly outside this import boundary.
- Both native editors have independent deadline and estimate controls, row badges and explicit floating/fixed-time selection. Shared quick entry accepts `~25m`, `~2h`, and `{YYYY-MM-DD}`. Escaped/quoted literals and declined planning chips cannot accidentally become planned dates. Recurring occurrences retain estimates and clear one-off deadlines.
- Exact `scheduled_at` timestamps preserve both 02:30 DST folds; the database rebuilds stale instants when older clients reschedule date/time alone. Tests cover Copenhagen/New York travel, date rollover, floating time, deadline independence, legacy caches and queued field persistence. Calendar/widget fixed-time presentation and hourly time blocking still require the later planner work.
- Closed a confirmed legacy privacy gap: unauthenticated email lookup and account-existence lookup are no longer callable. Email display is limited to one's own account, an inviter, or accepted members of projects one owns. Existing unrelated security-advisor findings remain a separate audit item; this does not claim a complete security review.

Verification: 53 Swift tests, one optional live test skipped, zero failures; 10 Deno fixture tests, zero failures; iOS and macOS unsigned app/extension builds; web production build and TypeScript check. The iPhone 17 Pro/iOS 26.5 UI test created a task through quick-entry chips, checked badges, relaunched and confirmed both editor fields. ## 5 October: hourly planner, local dates and calendar busy time

- Added a shared hourly **Day** view to both native calendars, alongside existing period views. Date-only tasks have an all-day lane; known estimates create sized blocks, while missing estimates stay dashed anchors and contribute zero known minutes. Overlapping blocks occupy separate lanes. Scheduling, dragging in 15-minute steps, resizing estimates and removing a time each use a single durable task edit and preserve the independent deadline. Mac changes register with the window Undo manager; iOS shows reachable Undo feedback. Each action also has scheduling/context/accessibility alternatives.
- The timeline uses actual elapsed minutes across 23/25-hour days. Repeated hours have time-zone labels; carry-over blocks clip to the selected day and retain their full estimate. Fixed instants are shown in the current local day. Today, Upcoming, calendar grouping, task-row date/time/zone badges, date popovers, date drops, bulk date moves and the notification “Tomorrow” action now use that same local day. A date move preserves the visible local clock and stored source zone, including choosing a consistent DST fold; a missing spring clock moves to the next valid clock time while preserving smaller components. Stored Gregorian dates remain stable with a different preferred display calendar.
- Added optional EventKit reads of explicitly selected calendars. Calendar events are never modified. Connection, selection and title visibility stay local to the current Taskfold account/device; event titles default to “Busy” and no event data is sent to the backend. Free, cancelled and declined events are excluded; unknown availability is counted conservatively. Empty selections read nothing. Unavailable/partial/denied calendar access has explicit feedback and does not imply complete free time. Actor-backed reads, account-generation guards and immediate clearing prevent stale event reads from repopulating another account. Debug test/preview workspaces use an empty provider and cannot read real calendars or request permission.
- Working hours use one bounded, validated JSON document in the existing owner-only `view_preferences` row `planner`, synced through the durable queue. This avoids invalid intermediate start/end combinations. Busy minutes are the union of selected event intervals within working hours; task estimates count as workload separately, including overlaps and all-day work. Unknown estimates are reported rather than invented. These are planning totals, not a guarantee of spare time.
- Repaired false task-edit conflicts caused by equivalent temporal spellings: native Z versus server +00:00, and native HH:mm versus server HH:mm:ss. The authenticated conflict RPC canonicalizes these values before its existing merge; real changed instants and different DST folds still conflict. The iOS conflict-review rollout is still pending and iOS has not yet been switched to this RPC.
