# Keep interface work responsive during sync-page decoding

Both independently owned apps previously decoded every downloaded workspace/history page synchronously on Backend's main actor. They now decode the immutable response on a user-initiated worker and return the complete value to that actor. This affects paginated task, project, profile, catalog and activity reads; page ordering, row limits, duplicate checks, cursor validation and access-boundary refresh behavior are retained. There is one awaited worker per page, not an unbounded set of concurrent page reads.

The worker uses the same fresh preserving decoder as before. Unknown authored fields, exact large numbers and canonically distinct Unicode keys retain their existing representation. Cancellation is checked before work, after decoding and after the await; a cancelled page cannot publish a successful value. An already-started page decode can finish before cancellation is observed; this does not run on the interface thread or write state. Both ordinary and history paths recheck the same account/session generation after the new suspension, and check cancellation before requesting another page.

Six new checks cover executor placement from the main actor, cancellation while the decoder is deliberately held, malformed-response refusal, exact unknown-value round trips, complete ordered 502-row pagination and refusal of a reversed history cursor. The held decoder test also requires the main actor to remain available to cancel and release it. Existing workspace access-churn, duplicate-page/profile-key and activity/preserving-JSON checks remain selected. These are local transport/Core checks, not new hosted, native-screen, speech or physical-device acceptance.

This removes one identified source of UI-thread CPU work. It does not establish universal smoothness or reduce the total decoding cost, and does not solve synchronous disk persistence, full snapshot encoding/decoding, initial layout, multiple-project rendering or physical frame pacing. Those remain tracked separately. No schema, provider, normal feature gate or user task data changed. Routine Mac updates remain authorized; phone installation stays deferred.
