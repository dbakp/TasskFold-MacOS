# Device-private location reminders

Status: rank-5 implementation in progress. Both apps own the data/one-shot lifecycle foundation and the protected private place/journal file store. iOS also owns a native map/search/radius/place-management component, reachable only through the exact isolated debug fixture while task delivery integration is unfinished. Normal app builds still offer no location-reminder choice, write no version-6 reminder and register no geofence. Current readers keep proposed settings opaque and emit no replacement planned-time alert. This is not completed location-reminder acceptance or completed Px work.

## Product behavior being implemented

The first lifecycle implemented here lets a person choose **Arrive** or **Leave** for a reviewed place and explicitly arm one notification on this iPhone/iPad. This is a foundation, not the final scope: the finished editor must also offer an explicit **Every visit until completed** choice, with corresponding repeated-trigger, response and cancellation tests. The current prototype intentionally accepts only `repeats: false`; repeated boundary alerts remain unfinished rather than being silently approximated with one-shot behavior. A saved place has a name, a reviewed pin and a 100–5,000 metre radius; 250 metres is the initial draft choice. Pin coordinates are represented in integer millionths of a degree. Boundary detection remains approximate and can be delayed by iOS, hardware, permissions and system settings. There is no continuous location log, polling trail or guarantee of immediate delivery. Arrive and Leave together, or a repeated alert, must not be inferred from a single one-shot selection.

Use Apple's [UNLocationNotificationTrigger](https://developer.apple.com/documentation/usernotifications/unlocationnotificationtrigger) with `repeats: false`. The system owns boundary detection and can notify without Taskfold tracking location in the background. Apple documents When In Use authorization for this trigger, rather than Always access. Native code must check actual availability and surface OS scheduling refusals. The app chooses a conservative maximum of 20 location alerts; this is not a promise that the OS will accept 20 triggers. The current Apple SDK explicitly excludes this trigger on macOS and Mac Catalyst. The Mac must preserve and explain the phone/tablet setting and support intentional removal; it must not request Mac location permission or reinterpret the reminder as a time alert.

### Places and consent

Saved place coordinates, radius and name remain inside the originating installation's account-scoped private storage. They must not enter task rows, widgets/App Groups, templates, share drafts, portable backups, task notification text or Taskfold backend requests. Deliberate Apple Maps/search use processes the viewed area/query with Apple as explained in the picker. Saving a reusable private place is a separate, clearly labelled action from saving a task reminder; cancelling a task must not leave an invisible armed notification. A place's pin/radius change creates a new opaque revision and requires affected reminders to be reviewed again. A rename alone retains the boundary revision.

The native implementation must provide reviewed map/search selection and optional **Use current location**. A map/address search sends the requested query to Apple's map service; it must be deliberate and explained. Current-location access is requested only after the user chooses it or enables location alerts. Use reduced-accuracy results honestly and allow pin correction. Apple documents that [reduced accuracy disables region monitoring](https://developer.apple.com/documentation/corelocation/cllocationmanager/accuracyauthorization); explain unavailable delivery and let the person choose Precise Location in Settings. Do not silently request temporary precise or Always authorization. Keep the existing notification permission/device-delivery choice separate, and add an explicit default-off location allowance for each account/device.

Private storage must use a dedicated Application Support directory, file protection, restricted file permissions, backup exclusion, bounded coordinated/atomic writes and a stable installation identity. Keep places until the person deletes them or the installation is removed; do not collect visit history. Account changes stop all owned location registrations and hide the other account's places. Returning to an account cannot silently revive a previously submitted/closed one-shot. Installation loss, restore or deleted private data requires new explicit setup. Missing and unreadable storage are different states: never replace a corrupt/unreadable journal with an apparently fresh one and begin registering alerts.

### Parity scope still open

The [current Todoist location guide](https://www.todoist.com/help/todoist/features/use-location-reminders-in-todoist-uGcwH2AJ6), checked on 22 October 2026, describes mobile Arrive/Leave alerts, address search, adjustable iOS radius, saved-location clearing and desktop/web authoring of mobile reminders. It does not specify a complete repeated-visit lifecycle contract. Taskfold must keep those authoring/management capabilities in its parity backlog; a handset-only one-shot implementation is not full location parity. Desktop-to-phone authoring needs a reviewed private handoff/account-only storage design so coordinates never leak into a shared task. That transport and repeated-visit behavior are not implemented by this foundation. No Todoist account data was read or changed for this documentation check.

## Implemented private storage and picker

`LocationPlaceStore.swift` owns a bounded account-scoped placebook and stable installation journal under Application Support/Taskfold/LocationPrivate, outside shared data and portable task exports. It uses a backup-excluded 0700 directory, 0600 atomic files, iOS Complete Until First User Authentication protection, a process writer lock and bounded reads. Missing state stays missing until an explicit save; unreadable/future state is refused without replacement. Stale edits and journal rewinds are rejected. Confirmed whole-installation reset creates a fresh identity. Account-level clearing keeps other accounts and the notification journal.

The iOS component supports deliberate Apple address search, map-pin/map-center selection, a name, 100–5,000 metre radius, explicit Save/Cancel, edit/delete and confirmed clearing. Renaming retains the boundary revision; moving/resizing changes it. Optional current location creates a one-use manager and requests When In Use only after a tap, with cancellation and a 20-second timeout. Search has a separate 20-second timeout. Query and selected-area disclosure is visible. No Always/background location capability is added. Native simulator checks and filesystem evidence are recorded separately in `p2-location-place-storage-evidence.json`; simulator search and file checks do not prove physical protected-data behavior or genuine geofence delivery.

Current native acceptance remains partial: iPhone search/save/relaunch/edit/delete and dark largest-text Cancel are exercised. iPad dark initial layout/Cancel passes, but the automated Search tap does not invoke its action; system accessibility errors persist after a non-erasing simulator restart. The app-versus-simulator cause is unresolved, so iPad search and saved-place flow are not accepted.

This component is intentionally behind an exact isolated debug route until task save/cancel, explicit device allowance, permissions, combined notification admission and native response handling are connected. macOS owns the same private storage contract independently but has no location picker/permission UI. Every-visit semantics and private desktop-to-phone authoring remain open.

## Proposed shared settings

Version 6, kind `location`, local-only channels and an explicit enabled Boolean wrap a version-1 `location_reference`. It contains only the originating device identity, original task ID/incarnation, private place ID/revision, one-shot arm nonce, Arrive/Leave choice and `repeats: false`. Taskfold's constructor writes no private geometry or place label. Unknown extensions survive supported settings toggles. The format is currently a typed prototype, not a new `ReminderSpec` capability or an app write path.

A reference is bound to its original task identity/incarnation. Copying, templating, restoring with a new incarnation, or completing a recurring task cannot retarget it to a different task. Actual `TaskCompletion` successor creation preserves the opaque row but the proposed planner refuses its old binding. The new task needs its own reviewed location reminder. Changing a task's planned date does not move the private place or create a new location opportunity.

The native save path must keep the existing workspace generation, task identity/incarnation, accessible-record and reminder-collection checks. A private place cannot grant access to a task. The planner accepts only currently accessible, unarchived tasks supplied by the existing authorization path. Duplicate task identities, duplicate place identities within an account, duplicate reminder identities and oversized reminder collections are refused. Duplicate boundary/transition settings on the same task are detected independently of their random arm nonces.

## One-shot lifecycle

The journal is owned by one installation. Before a task can arm a new reference, an explicit setup action durably prepares its ticket. Merely syncing a setting, reading a backup or finding a matching private pin cannot prepare that intent. The engine serializes preparations with registration writes. Preparing an intent before task hydration does not inspect, add or remove OS notifications; an explicit current plan is required before reconciliation.

Before calling the OS, transition **prepared → reserved** and durably save. A successful registration transitions to **installed**. The receipt binds account, device, original task/incarnation, completion revision, setting identity, place identity/revision, arm nonce and transition. Private geometry and place name are absent from receipts and notification content. Titles are snapshots of the task when armed; a title edit alone must not resubmit a potentially fired geofence.

A matching pending registration can recover **reserved → installed** after a crash, without another OS submission. A submitted registration that is no longer pending becomes **closed**, even if the app cannot tell delivery from dismissal, permission loss or an OS removal. A reserved request with no pending proof closes as ambiguous. Refusal or a boundary mismatch closes without automatic retry. Another opportunity requires a deliberate new arm nonce. A genuine later OS response can still match an original delivered/missing/ambiguous reservation while its current task/place/account binding remains valid; cancelled, failed, untracked and never-submitted prepared entries cannot authorize actions. Native response-origin validation, replay handling and actual task mutations are still required.

The engine fences each asynchronous reconciliation. If an account/desired-state change arrives while persistence or OS registration is awaiting a result, the old context cannot proceed to a new submission; a late OS addition is removed. Unreadable journals fail closed and clear only the owned location namespace. Undecodable owned requests must be reported for removal; time/Focus notifications must remain untouched. No journal history is silently pruned: at 2,048 entries, new preparation is refused. A future explicit reset must mint a new installation identity so old references cannot be treated as fresh opportunities.

## Combined notification admission

Location, ordinary task, snoozed task and Focus alerts must share the existing 60-request app budget. Locations use at most 20 slots, ordered by task priority then stable identity, without using the person's live position. Consumed entries cannot occupy capacity ahead of waiting reminders. The pure planner accepts the number of reserved slots; it does not independently prove or enforce the OS's global queue count.

Native integration must coordinate both schedulers in one serialized revision: first reconcile location removals without new submissions, then bring time/Focus requests within the budget reserved for the selected location intents, then submit locations. The cleanup-only mode preserves prepared intents without registering them. Keep budget reservations until stale/late work is cancelled. Two independent full-budget schedulers, or adding time requests before removing excess regions, can transiently overfill the OS queue and are not acceptable. Permission/account changes, OS refusals and snoozes must use this same admission path.

Verify process termination between reservation/add/acknowledgement, physical protected-data refusal/recovery and explicit identity reset without silently losing one-shot tombstones. Filesystem tests alone do not prove power-loss durability.
2. Connect native reviewed place search/pin/radius selection, private-place management/clear-suggestions, explicit Once/Every visit choice, explicit device consent and the existing task Save/autosave/Cancel/Undo paths. Show clear unavailable/changed-place/other-device/consumed states.
3. Implement the iOS system-center adapter and shared admission transaction. Keep the Mac's unsupported presentation lossless. Confirm local-only behavior during the existing remote-authority handoff before persisting the format; remote delivery remains deferred.
4. Validate genuine OS response origin and current account/task/place/nonce before Open, Complete, Move to tomorrow and Snooze. Reuse existing task actions, preserve plan semantics and reject stale/replayed/account-switched callbacks. Snoozes must not rearm the boundary.
5. Run iPhone/iPad Simulator native save/relaunch, permission refusal/recovery, actual pending-trigger inspection, synthetic arrival/departure and notification-action checks. Distinguish simulator evidence from physical-device background/locked/reinstall acceptance. Request real-device help only for a specific remaining behavior the simulator cannot prove.
6. Define and implement private desktop-to-phone authoring without putting coordinates into shared tasks; preserve unsupported settings on clients without that capability. Finish native Mac preservation, spoken accessibility, large text/light/dark and account-switch coverage. Keep the premium editing style and avoid technical identifiers in the final place picker.
