# Local filter drafting

Common complete descriptions can now prepare a filter without waiting for, or requiring, Apple Intelligence. The local path covers completion, explicit priorities, planned today/tomorrow/yesterday/overdue, independent deadline comparisons, named projects/sections/labels/assignees, explicit subproject scope, quoted text search, exclusions and same-field alternatives. It accepts polite introductions and sentence punctuation when those cannot be part of an unquoted target name. Every token must be consumed. Unknown, incomplete or ambiguous wording goes to the existing on-device model unchanged. This supplements the model; it does not replace its broader capability or claim to fix its known quality failures.

This is a separate description grammar. The saved-query parser and version-1 rule format are unchanged. Names are copied exactly and quoted; the ordinary current-workspace preview still resolves targets, permissions, directory/date bindings and stale inputs. No completion or project scope is invented. Relative dates remain relative. Multiple-word or ambiguous target names require quotes for the local path. Mixed-field OR, ambiguous week windows and other unsupported wording stay with the model/manual editor.

The assistant enables recognized local descriptions even when Apple Intelligence is unavailable, identifies whether a proposal came directly from the description or the system model, and automatically brings the result or error into view. Scrolling respects Reduce Motion and does not interrupt a focused editor. Preview and Use remain read-only; the existing editor must explicitly Save. Source/account/session/access/date checks and cancellation remain in charge.
