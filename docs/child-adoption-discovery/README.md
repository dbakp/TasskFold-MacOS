# Metadata-first access to older subtasks

This candidate lets Account → Subtask storage discover and review saved tasks without decoding their legacy subtask JSON or relying on ordinary editable task-cache rows. Discovery returns at most 100 identity/name entries, with a UUID keyset cursor, explicit shortened-name marker and single-root lookup. It deliberately excludes subtasks and never installs partial metadata into Snapshot.

The public discovery function runs with caller RLS. Its narrowly granted private helper checks the live authenticated session and adoption gate and returns only the caller’s account UUID. Selection remains under the caller’s table policies, including shared-project access. Titles are capped at 512 Unicode scalars; client pages are bounded to 300,000 bytes, reject duplicate/out-of-order IDs and refuse ambiguous cursors or unknown fields. Paging is live, not a frozen whole-account snapshot; Refresh starts a new traversal.

A selected root is freshly looked up before the existing review RPC. Its returned workspace is bound with the root generation/project and current account/origin/session/workspace/access/snapshot. Original JSON stays in the bounded raw-byte review parser. No normal task sync or cached authority is used to authorize adoption: send retains local pending/editor/encrypted-draft admission plus a fresh metadata identity check, while the existing server transaction enforces current permissions, archive/capability rules, exact digest, nonce identity and immutable receipt replay. An undecodable or access-fenced saved workspace may contain unknown pending edits or unresolved access recovery, so it explicitly blocks upgrade even while remote review/export remains available. Other writers’ ordinary cache requirements are unchanged.

The review list keeps loaded names in alphabetical order, with explicit Refresh and Load more controls. Search clearly covers loaded entries. Saved request names are read live when possible, scoped to the current account, and original retry/check/stop retains the existing durable command identity. Inactive/account/workspace changes clear view-owned discovery and raw source content.

Verification is recorded in verification.json after actual runs. Isolated empty-cache journeys exercise Store/View behavior with no editable task rows in an otherwise readable saved workspace; a separately undecodable-workspace mode must remain read-only; they do not claim to reproduce every real damaged cache or sign-in lifecycle. The database checks independently store an opaque JSON number beyond Double’s range, a precise integer and distinct Unicode keys, verify bounded metadata retrieval and unchanged source, and cover RLS, paging, expired sessions and gates. Existing 138 adoption checks remain in the harness.

No hosted schema, normal app gate, provider setting or real task is changed. Explicit malformed-content repair, ordinary editable-cache support for unrepresentable payloads, full shared attachment/discussion custody and client shared-workspace gate combinations, broader real account/secure-storage/window/background/VoiceOver acceptance, and user-deferred rollout remain open. This entry path does not make the normal full-task sync decoder accept those payloads.

Reproduce using this repo’s `node Scripts/Database/test-reviewed-child-adoption.mjs <report.json>`, the selected ChildTask Core tests, and the isolated native methods named in the report. The new migration was generated by Supabase CLI. The earlier isolated SQL harness is not a full local Supabase deployment/history check.

Reviewed the [Supabase changelog](https://supabase.com/changelog), [database function guidance](https://supabase.com/docs/guides/database/functions) and [RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security). Existing TLS and PostgreSQL notices do not change this metadata projection’s contract.
