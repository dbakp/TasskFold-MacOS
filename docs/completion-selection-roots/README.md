# Parent observations for mixed completion

This is the server read/admission contract needed before parent tasks can join the existing independent-child completion transaction. It does **not** implement or enable the mixed completion write operation.

The new read RPC returns 1–32 roots in caller order, each with its exact current task source, explicit identity/completion baseline, and a server-generated SHA-256 source fingerprint. It requires a live session, current editing access, active projects and the independent disabled `mixed_completions_enabled` gate. Team task custody and editing gates are rechecked. Heading, unstable/exhausted identity, busy-row and bounded-source failures refuse the whole read. Locks are acquired in stable root order.

A private guard helper validates every selected root, including no-ops, for the future atomic executor. Ordinary roots allow unrelated authored edits while completion/identity changes refuse the selection. Recurring roots also bind the exact source because it may be copied into a successor. This is an observation check, not a saved confirmation or mutation authority. The future executor still needs its complete resource/permission prelocks, whole transaction and receipt/recovery protocol before any mixed writes are exposed.

The only new public RPC is a read. Private helpers have no anonymous/authenticated/service-role execute grant; the public wrapper is an invoker and its private implementation uses a fixed empty search path with explicit live-authority checks. Baselines and fingerprints use UTC, and the actual read is invariant across caller time zones. No task, child projection, activity, request ledger, hosted schema/data or release configuration is changed by this milestone.

Each independently owned repository passes 65 actual PostgreSQL checks, with no added advisor findings and its owned container removed. Evidence covers private/shared roles, foreign Inbox isolation, expired session refusal, exact opaque numbers/Unicode, unrelated root edits, recurring-source edits, completion cycles, malformed/duplicate/bounded inputs, missing roots, archives, headings, busy rows, access loss after a read, paused gates, 32-root acceptance, individual/aggregate size refusal and execution grants. Exact source preservation is checked inside PostgreSQL; JavaScript numeric decoding is not used as proof. The raw PostgreSQL wire fixture is retained independently in each repo for the upcoming client decoder. No native or new client runtime acceptance is claimed.

Still required: typed bounded client decoding/transport, atomic mixed root/child writing (ordinary/recurring roots, private/shared projects, complete/reopen and same-branch ordering), immutable confirmations and request reservations, encrypted recovery, metadata-only terminal resolution, cross-journal admission, whole-selection Undo and premium native list/review/feedback acceptance. Full Redo/history, indexed mapping, custody and wider migration acceptance remain open. Normal app gates and this new server gate remain absent/off; user deferrals stay unchanged.
