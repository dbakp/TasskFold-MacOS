# Virtualize dated row cards without moving their drop targets · 7 November 2026

Today/Upcoming date holders stay measured eagerly, preserving the existing pinned-header and creation-highlight design. Their task cards now use lazy vertical stacks, so offscreen row views need not participate in each lift/layout update. The card styling, spacing, dynamic typography and public task-row identity stay intact. Only an invisible, noninteractive geometry registration changes identity with task/date. A retained frame is republished on reappearance even when coordinates are unchanged; owner-checked cleanup removes departed hit boxes without erasing a newer registration. Normal use persists no geometry state; synthetic DEBUG diagnostics are test-only.

A partially realized date is not the end of its task order. VisibleDayDrop keeps the insertion before the next ordered active task beyond the measured window, excludes completed rows from draggable neighbors, starts an unmeasured date before its first active task and retains the old rule for fully measured rows. Ten new cases and existing drag/context/date tests pass: 33 focused iOS Core checks, zero failures. The ordinary source/workspace intent validation and durable date/order writers stay in charge. No task schema, hosted service or normal rollout flag changes.

Settling publishes its expected destination before authoring so a synchronous layout callback can be admitted; a refused write restores the source day. Viewport restoration may wait for lazy geometry after the floating session ends, ends after stable readings, and yields to a pan or new gesture. Empty days reserve the same full insertion gap as populated days. This prevents source collapse from shifting the intended empty date under the finger. Apple's [lazy-stack discussion](https://developer.apple.com/videos/play/wwdc2026/321/) explains offscreen estimates and layout changes; this implementation keeps section geometry and tests the actual behavior rather than assuming a lazy container alone is sufficient.
