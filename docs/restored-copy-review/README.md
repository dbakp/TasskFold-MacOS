# Compare copies during an active older-structure restoration

The storage owner or a current workspace owner/admin can explicitly review the older task tree and the newer snapshot/records held during restoration. Ordinary saved-copy reads still omit divergent unproven content. This is a read-only service/client foundation; the native comparison screen and final action that keeps the older version editable are not implemented by this change.

The new invoker endpoint `taskfold_review_restored_child_copies` takes the fresh standard review identity plus the restoration's actor and ID. Its private lookup revalidates the live session, root generation/project/storage owner, current workspace administration, active restoration phase, exact restored target, retained payload and current/retained file manifests. Root and history RLS are checked by the caller-facing wrapper before returning content. A second current administrator can review another actor's restoration; a project editor without current administration cannot.

The response contains a normal bounded saved-copy comparison and an explicit restoration actor/ID/revision/digest binding. The digest includes the full current root, retained inverse, current record snapshot and file manifests. It carries no editing authority and is not yet accepted by a save command. The inverse payload itself is not returned. No new scope table, permission flag, editing exemption, ledger entry or content mutation is introduced. Existing active-restore write/move fences and immutable retry/Undo/Redo/Finish behavior remain intact.

Each client keeps this response ephemeral, validates its exact restoration identity and current review context, preserves raw source/export bytes, checks integer spelling and size bounds, and discards results after a session change. Descriptions contain no private content. The Store checks account/workspace/snapshot freshness before and after loading. No native view calls the new method yet; normal advanced flags remain off.

Verification uses each repository's complete owned migrations and genuine isolated Auth/REST/Storage services. It covers personal and shared custodians, role demotion/recovery, unrelated/anonymous actors, inactive and incorrect restorations, task/history RLS denial, unchanged protected content, exact large/unknown values, and the surrounding restoration cycle/Finish regressions. The captured contract preserves the actual response text; an earlier exporter rounded its nested source and was corrected after the strict client rejected it. No client validation was weakened.
