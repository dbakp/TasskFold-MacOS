# List completion through saved child commands

Single-child list actions use the existing independent completion journal, not a rewrite of the parent checklist. An immutable click intent retains its account/session/access scope, parent identity, raw full child path and observed completion cohort. Fresh reads reject stale owner/project/incarnation/state changes. A completion token allows disjoint field edits; legacy children require the captured tree to remain exact.

The Store serializes local list preparation across windows, stages the command durably and sends through the existing idempotent protocol. Only a confirmed matching command offers Undo. Undo reads fresh data and uses the original confirmation proof. A prior Undo receipt cannot certify a later failed action. Uncertain results retain their original saved request and expose Review directly from the list confirmation. Scope changes clear the new confirmation/review controls.

Mac checkbox/context-menu/single-selection keyboard actions share the entry point; Undo uses the window undo manager. iOS enables the contextual child check control and offers receipt-based Undo in its existing toast. Root tasks retain their existing behavior. Broader bulk, redo and shared history integration remain unfinished. Child-containing bulk completion is refused before the legacy writer; it is not silently applied as a parent-tree edit. A fresh read currently requires connectivity.
