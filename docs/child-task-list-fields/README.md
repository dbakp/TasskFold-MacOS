# Selected-child fields from the normal task list

The Mac inspector and iOS task-editor presentation now route a selected virtual child to the field-command editor when its existing rollout gate is enabled. The nested organizer link also carries its selected reference. A frozen opening binds the workspace, parent identity and full raw child path. Missing/moved paths, different Unicode spellings and changed account/parent identities cannot silently fall through to the first child. The ordinary parent/legacy route remains available behind the existing gate decision.

The selected-child detail hides the general child picker, global organizer and routine recovery controls. A single Save changes action durably stages the supported fields and then explicitly sends the same saved command while the editor/scope/revision remain current. Confirmed changes refresh the field baseline and list; the save button returns disabled with Changes saved. Uncertain replies keep the durable request for explicit review/retry. The recovery tool retains its separate private-save/send workflow. Editing after clicking Save cannot be discarded by its later confirmation: revision is checked again after the awaited send.

The debug-only fixture mounts the real Inbox/list/inspector/editor screens with synthetic data. It suppresses generic UI-test local seeding and real-time networking only for the reserved test identity. The final native controls use the normal app layout rather than the diagnostic fixture panel.

On iOS, expanded Inbox/project rows now expose child tasks in authored order, with nested expansion and completed-ancestor visibility. These contextual rows open the selected detail; their legacy completion, swipe mutations and bulk actions are unavailable until the child-command integration is finished. Reordering is disabled while a group contains expanded child rows, so contextual indices cannot reorder stored roots. Dated, search and hierarchy-filter scopes keep their existing presentation.
