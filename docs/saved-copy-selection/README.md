# Saved-copy selection in the apps

Both independently owned apps now let a reviewer choose a readable task list, saved snapshot or stored-record copy from the existing comparison. The choice is saved locally before previewing. It stores only the source and exact comparison fingerprint, never a replacement task tree. Choosing a copy is a separate action from format/hierarchy repairs; it cannot be combined with them. Undo/reset returns to comparison.

The existing review shows the proposed task list, asks for confirmation, queues the exact saved request, and supports send/check/stop recovery and original export. A cold return restores the source and fingerprint. A lost reply keeps the original request for status recovery. Current-account, session, window/snapshot, pending-edit and cache-recovery gates still apply. A changed comparison clears the old preview and requires Undo/reset and fresh selection, preserving the draft. Unsupported identities or completion/recipient histories stay blocked by the server.

Original export now accepts the new complete archive: root, projection, records, authority, root/child history and the exact copy choice. It verifies archive size/hash, task generation/project and request/review identity, plus the selected source and comparison fingerprint. It does not import that archive into editable state. Existing format-repair originals retain their previous stricter null/empty indexed-storage contract.

## Evidence and limits

- `client-verification.json`: 75 passing core tests per repository, including five new choice/archive/draft/recovery tests. The fixture comes from that repository's actual disposable PostgreSQL run. Its canonical archive representation is checked against the actual server digest and byte count before use; the client verifies them again. Wrong choices and incomplete archives are rejected even when their test envelopes have matching recalculated hashes.
- `native-verification.json` records the passed normal-text iPhone journey: compare, choose, Undo/reselect, cold draft, save once and cold confirmation. `phone-proof.json` independently verifies the exact chosen tree, all three originals, archive size/hash and absence of unrelated writes. Four final screenshots and one earlier largest-text selection capture are retained in the iOS repository. The Mac direct flow now also passes comparison, choose, Undo/reselect, genuine cold draft, explicit save, cold confirmation and actual native original Save/readback with exact archived bytes; see `mac-direct-summary.json`. Full largest-text recovery and other Mac workflows remain open. Current icon-only builds are in `icon-build-verification.json`; the full workflows were not rerun after that single resource-name correction. The current Mac build separately verifies the visible corrected icon and a distinct-process cold saved review, then Undo, preserving exact peer bytes and the one previous save. A synthetic file-backed peer exercises app controls; it is not evidence of genuine-account HTTP delivery or SQL authorization. The real transaction and permission/rollback tests are in `../copy-choice-reconciliation/`.
- Full older-data migration, ambiguous identity/completion/recipient mapping, opaque editable caches, shared file/discussion custody and surviving-member archive discovery remain unfinished. Other Mac workflows and wider account/window/privacy/speech/library acceptance remain separate.

Normal-use adoption and repair flags remain absent/effectively false in both app projects, and the new server copy-reconciliation flag defaults false. No hosted project was changed. All previously agreed release/provider/device deferrals remain deferred.
