# Reviewed voice drafts

## Use

Open Add multiple tasks, then Dictate tasks. Choose the language and explicitly start recording. Stop when ready, correct the transcript, and choose Apply. Applying appends the transcript to the original task text; it does not create tasks. The existing Review tasks screen still shows titles, dates, priorities, destinations and exclusions before Add saves anything. Another recording adds a line. Ordinary conjunctions are not guessed to be task separators.

Cancel discards the unapplied voice proposal and leaves the original text unchanged. Permission refusal, recording errors and Stop retain text already in the voice review so it can be corrected or applied. Leaving the foreground stops audio input. The same presented review can retain text on return; this is temporary in-memory UI state, not a promise to restore an unsaved transcript after app termination. Saved tasks retain the existing persistence/sync/Undo contracts.

## Recording and privacy

Each app independently owns its Speech/AVFoundation adapter, Core state, native view, project inputs, privacy descriptions and tests. No sibling repository is needed to build either app. Speech and microphone access are requested only after Start, never when opening the review. The driver checks `supportsOnDeviceRecognition` and requires `requiresOnDeviceRecognition` on every request; unsupported languages/devices fail explicitly, with typing still available. It rechecks support/availability after permissions. There is no server-transcription fallback or AI service. These checks follow [Apple's on-device support contract](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition) and [request requirement](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition).

Live audio goes from an AVAudioEngine tap into a serialized in-memory speech-request sink. Taskfold does not write audio files. A per-process recording lease prevents two Taskfold recording drivers from taking over each other's session. Input stops before finalization; the driver removes its tap/observers, ends audio and releases the engine. On iOS it deactivates its recording session and restores the prior category/mode/options. A recording stops after one minute. Finalization accepts a final correction for up to two seconds, then freezes the available transcript for review. Accuracy, device support and genuine permission/audio behavior remain acceptance gates below.

Both Info.plists own microphone and speech usage descriptions. The sandboxed Mac app also declares microphone and audio-input access. Relevant primary references: [speech permission](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition), [ending audio input](https://developer.apple.com/documentation/speech/sfspeechaudiobufferrecognitionrequest), [Mac microphone access](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.microphone), [audio input](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input).

## Draft safety

A voice proposal captures the request identity, workspace incarnation and original text. Each recording has a separate callback token. Partial results replace only the current recording segment and preserve earlier corrected lines. Results from cancelled/superseded recordings cannot overwrite later edits. The current workspace is checked after every permission wait and before input starts, as well as on callback delivery. Changing workspace or replacing the review closes its recorder. Applying requires the same request and unchanged parent text; a second Apply cannot append the proposal again.

Text is bounded to the existing 100 KB multiline intake limit. Oversized results are rejected without truncating or replacing the earlier valid text. Unicode and authored lines are retained. The existing parser owns task proposals, its 200-line limit and destination validation; no second task schema or speech-specific mutation path is introduced.

The iOS review uses a normal inline title, a shorter Apply control with a full accessibility name, and a wrapping language control at accessibility text sizes. The transcript scrolls into view when its keyboard opens. Permission notices sit beside the recording controls. Native Mac component previews preserve the existing grouped-form style; they are not a full-app interaction claim.

## Verification and remaining acceptance

`VoiceDraftTests` in each repository checks partial replacement, multiple recordings/corrections, cancellation, request/workspace changes, invalid input/limits and the existing parser handoff. The Mac's `Scripts/test_voice_capture_controller.py --output OUTPUT_JSON` compiles the production model/controller with a synthetic recorder. It tests late events, refusal, finalization, context rejection and the real one-minute timer. It opens no microphone or permission prompt. `Scripts/render_voice_draft.py --output PREVIEW_DIRECTORY` renders the actual Mac view with a minimal read-only Store fixture, without loading real accounts or posting input.

The iOS native fixture is compiled only in Debug and requires the exact disposable app bundle, `ui-testing` workspace, `--uitesting` and `--voice-fixture`. It supplies synthetic transcription/refusal events; it never represents real microphone/TCC acceptance. Phone/tablet UI cases cover correction, Cancel/source preservation, Apply without a task write, explicit bulk save, exact persisted tasks after relaunch, refusal and largest-text dark layouts. Exact runs and follow-ups are in `p2-voice-drafts-evidence.json`.

Open gates: genuine on-device recognition on supported hardware/languages; real permission denial/recovery; microphone/route/call interruptions and iOS audio-session restoration; foreground/background and simultaneous-window recording; actual account/draft changes during capture; Mac native keyboard/selection/Undo and VoiceOver; wider localization/RTL/large-system-text layouts. The Mac desktop is locked, so full native interaction is unverified. Model/fixture/build success does not close those gates. Cloud AI assistance, the user's release/provider/push/older-client deferrals and the rest of Px remain unchanged.
