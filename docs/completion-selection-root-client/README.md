# Typed parent reads for mixed completion

Both clients now own the same typed, bounded root-observation protocol and backend read method. The decoder accepts the actual PostgreSQL wire fixture from each repository's independent database run. It binds account and requested task order, requires exact identity/completion baselines, validates digest shape and counters, and preserves opaque numbers and distinct Unicode metadata keys. Legacy null heading/repeat flags remain null rather than being normalized. This is a read, not a saved completion confirmation or permission to write.

Requests contain only account and up to 32 canonical root IDs. They use the existing private no-cookie/no-store/redirect-refusal path, with a 4 MiB streaming response ceiling and per-root source bounds. The new byte consumer runs off the UI actor; bounded decoding also runs in a cancellable background task. Account/session/origin checks fence both success and failure, including a late refused response after account replacement. Known live-session refusal retains its sign-in-required type.

Typed observations prepare root-only or mixed root/child selections through the frozen selection preflight. The selected root set must match the read. Child reads must have the same scope and exact root snapshot; unrelated child branches, including children of headings, are supported without pretending that an unselected heading parent should complete. No-op observations remain available for server guards, and those guard bodies exclude full task trees, notes, attachments and other source fields.

Each repo accepts 143 scoped Core cases, including 23 new protocol/transport/preparation cases and 120 related regressions. Mac's initial 18-case findings are retained separately. The same synthetic 2.2 MB response case initially took 34.828 seconds before failing metadata validation; the accepted case is under a second after the isolated off-actor consumer and nullable-flag fix. These are local diagnostic timings, not native-device, network or general product performance benchmarks. No new SQL run, native build/runtime or full-product acceptance is claimed; the earlier 65-case server acceptance remains historical.

Still required: integrate the combined root/child atomic completion/reopen transaction, strict immutable confirmations and request reservation, encrypted mixed recovery and terminal resolution, cross-journal admission, whole-selection Undo and native list/review/feedback acceptance. Typed methods alone do not make mixed completion available in the app. Full Redo/history, mapping, custody and wider migration checks remain. Normal app/server gates remain absent/off, hosted schema/data remain unchanged and user deferrals remain in place.
