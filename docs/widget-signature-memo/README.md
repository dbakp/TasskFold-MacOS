# Reuse computed widget completion hashes during saves

Each Store now owns a caller-confined cache for root completion signatures. It binds the account/workspace generation, actual sign-in incarnation and presentation-access epoch. Missing scope disables retention; unreadable workspaces clear it, and sign-out/removal-blocked saves use the uncached path. The default limit is 4,096 entries; IDs longer than 256 UTF-8 bytes compute normally without retention. Entries hold only a bounded ID, derived hash and opaque immutable source token. That token holds no Record or task fields, so this optimization does not retain notes or large task text. It is not Codable and supplies no authority.

The memo reuses only its own computed hash for the exact same immutable Record value. Every fields write retires that record token, and fresh decoded records need computation unless exact refreshed-row reconciliation has already proven their values. It never trusts the saved widget signature or stores widget action tokens. Existing state comparison, UUID generation, pruning, receipts and feedback remain. Child hierarchy/context and child hashes are still checked on every call, including when root hashes are reused. Off-interface command preparation keeps its existing uncached path; no mutable memo crosses that worker boundary.

Fourteen new functional cases cover unchanged/current fields, irrelevant edits, fresh decode, workspace/session/access changes, missing scope, explicit privacy clearing, limits/deletions/oversized IDs, tampered widget signatures, model rollback, duplicate IDs, proven refresh hits and child edits/filter removal. Both owners pass 76 focused Core cases with the explicit diagnostics enabled. The existing legacy/canonical signature, 5,000-row/distinct-instant, hierarchy/action and prepared-encoding cases remain selected. The rollback case is a model check, not a new native disk-failure journey.
