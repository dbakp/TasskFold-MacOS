# Reviewed restore controls and saved-request recovery

Reviewed 7 November 2026. Saved originals now opens a restoration review and a device-local saved-request browser. Review presents current/after structures, positional outlines and bounded source disclosure. Applying requires an explicit acknowledgement. Confirmed actions offer a fresh Undo/Redo review; unresolved actions expose Check status, Retry this request and Stop. Current task notes/priority stay current; the older subtask structure is read-only until Undo.

The exact small command is encrypted and saved before sending. Cold recovery retains its original identity, and an ambiguous reply is resolved by Check rather than inventing a new request. Closing, account/session/access/background changes cancel the display model without discarding the pending command. Confirmation is validated against every command field, phase, revision and restoration identity. A result does not install partial task rows; the app refreshes through its existing sync.

Review sources remain opaque and ephemeral, are decoded away from the interface thread, and preserve unsafe numeric tokens, Unicode and unknown fields. They never enter the request journal. Existing child-action journals refuse a conflicting pending restoration under their shared process lock; restoration admission checks other child actions, open editors, pending root edits and preserved edits. Status and Stop do not depend on the sending switches. A separate Subtask restorations entry is discovered from its own encrypted journal, including unreadable state, so disabling archive/repair authoring does not hide recovery.

Both owners pass83 focused Core cases, including14 new restoration cases and all10 recovery-discovery cases: actual service metadata/decision contracts, opaque lexical stress, strict scope/phase/counter validation, encrypted cold state, conflicting roots, lost replies, failed/ambiguous secure writes, account changes, stale review, paused sending with Stop, and actual Backend URLSession routing/error handling through a local protocol double. This is not native HTTP Auth acceptance. The earlier191-check genuine local API/Storage evidence remains separate. The final recovery-entry integration also runs all10 discovery cases across the new ninth journal family; current totals are recorded in verification.json. See verification.json for build/source scope.

## Still open

Native restore → lost reply/status → cold Undo/Redo interaction with the actual service is not yet accepted. Full app compilation is reported separately from Core and from interaction. Wider Mac/iPad/speech, current/cold rendering and physical performance remain distinct. Server-side retained-history disposal/keep-old-version adoption, task/account/custodian lifecycle, audio and broader legacy-file ownership are still required before activation. Confirmed local receipts are retained because they currently hold reversal identities; wider server discovery/retirement must finish that lifecycle.

The two client switches are absent/off in normal configurations; the two service switches remain off and no service is deployed. Only the reserved compilation host may enable the client switches. No normal app update, phone installation, rollout activation or new curated completion checkpoint belongs to this batch.
