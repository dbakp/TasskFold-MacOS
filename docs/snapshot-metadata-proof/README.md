# Snapshot metadata preparation

Saving no longer serializes unchanged metadata repeatedly just to prove that the worker's bytes still match. Snapshot carries an opaque, unencoded metadata identity. Each metadata property write invalidates it; assigning nil to an already absent optional field is an exact no-op. Table buffers retain their separate identity/key/count proof. Independent/recreated metadata still takes the existing sorted byte comparison, including Unicode/signed-zero distinctions and encoder failures.

The identity deliberately does not participate in Snapshot's domain equality; it is compared explicitly for byte reuse. A fresh decoder cannot import it, and it has no account authority. All existing initializer parameters and Codable keys remain. No fields/action tokens are retained in the identity.

The widget-preparing worker also runs the existing private-ledger metadata decoder. Its private result and exact metadata bytes travel with the prepared encoding. The final read memo reuses validation only after complete input admission. Invalid, changed or oversized metadata keeps the ordinary validation/no-memo path; the 512KiB metadata limit remains. Actual durable-ledger staging, account/access guards, atomic writes and post-save publication remain. A redundant matching call used only by DEBUG diagnostics is now DEBUG-only in both Stores.
