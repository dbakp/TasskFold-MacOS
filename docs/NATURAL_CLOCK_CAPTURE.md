# Natural clock capture and next-day planning

Both native repositories independently accept `in the morning` (09:00), `in the afternoon` (12:00), `in the evening` (19:00), and the standalone periods `morning`, `afternoon`, `evening`, `night` (22:00). These complement noon, midnight and strict numeric clocks. The exact phrase becomes a removable time chip. The parser protects quotes, escaped complete phrases, URLs and word boundaries. Multiple clocks or an explicit period plus elapsed time stay literal with one ambiguity warning. Independent dates, deadlines, priorities, estimates and reminders retain their meanings.

For a task with no valid plan and no independently accepted date/repeat rule, a clock means today until its resolved instant has passed, then tomorrow. The preview chip says **Tomorrow** when it derives that date; declining that clock removes both derived fields and retains its exact text. Existing valid plans, context defaults, explicit today/yesterday/future dates and the first date selected by an accepted repeat rule remain chosen even when their clock has passed. This changes newly captured time-only tasks from the previous same-day behavior; it never migrates stored work. Midnight starts its chosen day.

Rollover resolves a Gregorian wall minute in the task's fixed source zone, or the supplied planning/viewer zone for floating work. It uses the existing first-fold/next-valid-minute resolver, compares the actual instant, and adds a calendar day instead of 24 hours. Tests include Copenhagen gaps and repeated clocks, Lord Howe's half-hour transition, Apia's skipped day, travel and a non-Gregorian display calendar. Existing canonical `HH:mm`, planned day, source-zone and scheduled-instant fields are retained. The durable native save path continues to normalize scheduled instants. No schema, AST capability, queue vocabulary, widget payload or sibling dependency is added.

Cursor suggestions accept `in the mor`, `in the aft`, `in the eve`, and unique standalone period prefixes. The short `ev` prefix retains repeat suggestions; it does not silently switch to evening. Candidate previews use the actual task parser, including the derived day and retained later prose. Independent reminder clocks accept `!tomorrow morning`, `!tomorrow evening`, and `!every day afternoon`; they use existing reminder specifications and never create a task plan. Absolute reminder future checks and recurring reminder anchor/source-zone rules remain in force.

The iOS composer gives chips their full single-line width at accessibility sizes; the existing horizontal scroll area reveals long labels without text escaping the capsule. Native macOS chips retain their full text in the existing horizontal scroll area. Both platforms retain their existing appearance, navigation and keyboard actions.

The [official Todoist date/time guide](https://www.todoist.com/help/todoist/features/schedule-a-date-and-time-for-your-todoist-tasks-q7VobO), checked 7 October 2026 (updated 28 August), documents the morning/afternoon/evening times and time-only rollover. This closes those quick-entry implementation gaps. Configurable next-week/weekend settings, Todoist next-weekday interpretation, short combined aliases such as `tommorning`, richer date/repeat grammar and the remaining P0 requirements still need work.
