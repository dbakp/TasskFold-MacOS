# Local effort and assignment filter descriptions

Both independent owners now prepare clear effort descriptions locally, including “Open tasks estimated at 30 minutes or less,” “Tasks taking up to 1 hour,” and “Tasks estimated under 30 minutes.” Minutes/hours convert within the existing 1–10,080 minute filter range. Inclusive and strict bounds differ correctly. Missing estimates do not match. Exact, lower-bound, fractional, combined-unit or incomplete wording is not silently turned into an upper bound.

“Assigned by me,” “assigned by others,” “assigned by unknown” and quoted collaborator names use the existing recorded-assignment predicate, separately from “assigned to.” Keyword OR alternatives are supported; arbitrary words after OR are not inferred as people. Existing current-directory resolution, unknown-history logic, target revalidation, preview and explicit Save remain in place. The implementation consumes the complete description and preserves joins with priority, planned dates, completion and projects.

Each owner independently compiles and runs 57 selected Core cases: 55 pass and two opt-in model probes skip. Five new behavior cases verify actual matching rows, edge estimates/missing values, combined conditions, real actor-versus-recipient history and the local engine origin. The first iOS run caught unsupported OR shorthand; its implementation and negative coverage were corrected before the accepted runs. No model inference, service, schema or normal-gate change occurs. This is new product behavior with Core acceptance, not new full-SDK, native UI, model-quality, language or device acceptance. Installed Mac53 and deferred phone installation are unchanged; include this in the next coherent app update after provisioning is available.

End-of-run cleanup removes only completed owned SwiftPM module scratch (about48MiB); reusable Core caches remain below768MiB. No Simulator is booted and no user data, backup, Keychain, Docker volume, SDK or other project is touched. Full Px work remains active.
