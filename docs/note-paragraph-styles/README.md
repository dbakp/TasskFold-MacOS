# Note paragraph styles · 6 November 2026

The note editor now offers Body, Heading 1, Heading 2 and Heading 3 from its Text style menu. Changing the level replaces an existing Markdown heading prefix, rather than stacking a second prefix. Body removes the heading prefix. Empty headings select a placeholder for immediate typing. H1, H2 and H3 use distinct scalable native font styles in the preview/reader. Command–Option–0/1/2/3 are attached to the corresponding menu choices for hardware keyboards; a physical keyboard or spoken walkthrough is not claimed here.

The pure transformation expands a text selection to the selected lines, preserves adjacent source bytes, indentation, blank lines and original line endings, and leaves non-heading hashes and other markup literal. Both selection boundaries must be valid grapheme boundaries in the original UTF-16 range. Inputs and resulting formatted text remain within the existing 512,000-byte formatting budget. The existing heading shortcut API retains its H2 toggle behavior while normalizing other heading levels.

No task identity, date, completion, pin, project or shared-data contract changes. The editor keeps its existing guarded description-only Apply/Save, recovery checkpoint and explicit discard paths. Notes remain ordinary portable Markdown text, with the exact original-text view available. Task-heading rollout and all provider/older-client/distribution deferrals remain as recorded.

Each repository independently owns the Core transformation, SwiftUI control and focused tests. The platform-specific editor/test hooks remain intact. The focused suite includes 8 new paragraph cases plus the existing formatting/markup/source-binding checks, 37 tests per owner. The iOS native case extends the existing focused note journey to exercise changing levels, Body, preview, explicit Save, actual Store Undo/Redo and cold text preservation. Its signed products and outcomes are recorded separately from Mac compile/sign acceptance; Mac native interaction, hardware keyboard, wider accessibility/account/cloud and physical rendering acceptance remain open.

The initial native test assumed that a center tap left the caret at the end and expected a new trailing placeholder. It reached the new controls but failed that assumption. The revised check identifies the selected paragraph from the H1 result, verifies exact H2→H1→H3 changes and checks every other line unchanged. No production guard was weakened for that correction. An editing-script file mix-up in the Mac Core copy was also corrected before its first build; the owning 37-test Core run verifies the corrected implementation.
