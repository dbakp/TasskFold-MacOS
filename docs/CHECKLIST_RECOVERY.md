# Reviewed checklist recovery

Open a task → **Organize subtasks**. A checklist with missing, duplicate or unreadable references opens a recovery review instead of editable rows. Review names and affected nesting, inspect **View original data** if helpful, then choose **Recover in this draft**. Existing shortcuts to recovered items must be opened again. All nodes sharing a duplicate reference receive new references; keeping the first occurrence could silently retarget an old selection.

Recovery keeps recognized object nodes' names, notes, completion, scheduling, assignment, labels, discussions, attachments, unknown fields, sibling order and nesting. Only affected `id` values change; valid unique legacy references remain unchanged. Text-only legacy entries become named open subtasks after explicit review, preserving their complete text. No separate backend child-task record is created. Newly allocated references are canonical UUIDs, avoid every saved reference and each other, and stay stable for that review. Empty names still need the organizer’s normal name validation before Save.

**Recover in this draft** does not persist a task. Cancel discards the organizer draft. On iPhone/iPad, organizer Save updates the parent editor; Save the task to persist. Mac organizer Save uses its existing inspector autosave/Undo transaction. An optional Save and open details action persists through the normal guarded callback. Source checklist, root task and workspace are rechecked before applying or saving. A concurrent source change refuses the old review. Existing task save/queue/concurrency and Undo rules remain in force; recovery never merges an unfamiliar tree by guessing positional identities.

Preparation runs away from the UI actor and supports cancellation. No original source is edited while loading or generating a review. Recognized content is bounded to 10,000 nodes, 32 total nested child levels (including an embedded editor’s existing depth), 100,000 JSON values, 128 JSON container levels and 2.1 MB of encoded original and proposed data. Metadata counts toward the bounds. The normal hierarchy index also validates the complete proposed tree and its 32 MiB reference-storage bound before it can be applied. Oversized/deep/unrecognized content refuses as a whole; no partial subtree is returned or saved. New references are allocated once for the presented review, with a bounded collision retry. No permission, credential or backend access is requested.

An unknown root/node/title/children structure stays unchanged. The review offers a selectable original JSON representation and a system Share action; viewing uses literal text, never Markdown, executable URLs or web fetching. Sharing is an explicit user action through the system; Taskfold does not upload anything automatically. Original viewing uses the same encoded-size/complexity bounds; larger content remains retained in the task and existing workspace backups. This is semantic JSON preservation, not a claim to preserve an external file’s original whitespace. Unknown formats require a supported producer/update or manual investigation; the app does not invent task names or discard opaque branches to force them into the editor.

Inline completion/text editing is disabled for text-only or unknown nodes while their legacy text remains visible. Adding cannot replace an unknown non-list container with an empty list, including keyboard submission. Native Mac child lookup and replacement now reject duplicate/positional-key collisions and unknown node shapes instead of selecting the first match. Existing unique positional legacy paths remain readable; explicit recovery supplies durable references. These safeguards do not implement the separate future independent-child-task contract or non-completable headings.

Both repositories independently own Core/UI/tests. There is no backend migration, new shared task field, app permission, file type registration or sibling build dependency. Exact checks, screenshots, source hashes and acceptance limits are in `p2-checklist-recovery-evidence.json`. Native Mac interaction, spoken accessibility, paired cloud/offline concurrent edits, broader localization and arbitrary future-format recovery remain separate acceptance work; none of the user-deferred release, remote, older-client or OAuth work is reopened. The full rank-3/Px objective remains incomplete.
