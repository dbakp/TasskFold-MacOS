# Daily-use update candidates · 6 November 2026

This update packages the current ordinary app source, including note paragraph styles, prepared note reading/section navigation and filter/member-read improvements. Existing advanced and server-dependent rollout gates stay as recorded; no hosted migration or function is deployed by building a candidate. The installed apps and their data are not replaced by these commands.

Each owning repository now has its own cached development-profile preflight and archive/readback command. The selector requires an exact app/team/platform identity, an unexpired profile and a currently available Apple Development signing identity. Phone profiles must allow the requested registered device; Mac profiles must allow this Mac’s provisioning identifier. Every requested app/extension needs a matching profile. Xcode-managed profiles retain automatic signing; non-managed profiles use their explicit manual profile. `--allow-provisioning` is incompatible with `--cached-profiles`, and the final embedded profile UUIDs must exactly match the validated cache before a successful candidate receipt is written. No profile contents, certificates or credentials are created or modified.

The package command requires the owning signed receipt, exact current app/source/build-tool inputs and, when supplied, a preserved earlier baseline archive. It builds a new ZIP, extracts it into a private system temporary folder, compares files/symlinks/permissions, verifies the signature and embedded profiles again, and runs the existing owning metadata checks. Publication uses exclusive same-filesystem links and cannot overwrite an older candidate. Failed publication removes only that run’s own link. Normal app sessions, Keychain data and task stores are untouched.

The first phone build correctly rejected forcing Xcode-managed profiles into manual signing. Keeping their supported automatic mode then produced the signed Release candidate. The first package check also caught FinderInfo added when readback occurred under Documents: the exact same archive verifies in the system temporary directory and fails strict verification under Documents. Readback now uses that isolated temporary folder; verification is not disabled and the app is not re-signed. Apple’s [code-signature guidance](https://developer.apple.com/documentation/xcode/using-the-latest-code-signature-format) is retained as the reason to keep iPhone signing inside Xcode. The first Mac preflight used the wrong case for a system metadata key; the actual `provisioning_UDID` field is now used before profile selection.

Seven focused tooling checks pass per owner: six profile-selection cases and one failed-preflight stale-receipt guard. Selection cases cover exact identity/device matching, expiry, wrong team/platform/UUID, unavailable signing identities, distribution-profile refusal and complete target families. Genuine Xcode signing and final archive readback are separate evidence. These are personal development candidates, not App Store/notarized release acceptance or universal current-device feature/FPS acceptance. The known development-profile expiration and incoming phone Share-extension omission are recorded in the candidate receipt. All remote-reminder, older-client, distribution, provider and phone-installation deferrals remain.

Commands run from the owning checkout:

```sh
python3 Scripts/build_daily.py --cached-profiles --build-number BUILD
python3 Scripts/package_daily.py --receipt BUILD_RECEIPT --output OUTPUT_DIRECTORY --baseline-receipt PRESERVED_BASELINE
```

For the phone, also pass the existing registered `--device`, `--offline-device` and the explicitly recorded development-only `--without-share` option. That builds without connecting or installing on the phone. Source projects and release entitlement files remain unchanged. No sibling repository code or products are used.
