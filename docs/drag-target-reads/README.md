# Reuse active drag targets · 7 November 2026

Dated iPhone drags now group current readable presentation rows once per active gesture/context, then retain one ordered priority-band read for each visited date. Pointer updates use the anchors directly. Source snapshot, account/generation, access, presentation mask, session, time zone, manual-order mode and readability changes invalidate the read. Release rechecks the current context even after a stationary pointer. End, Cancel, scope/query/workspace changes and view exit release the gesture cache. Returning through Today/Upcoming configures a new gesture read. Final source-intent validation and the ordinary durable date/order commit remain in charge.

Mac's existing drag coordinator now retains immutable priority anchors per destination, invalidating them on dragged IDs, order or priority inputs. Exact old priority semantics remain, including unsorted rows, excluded multi-selection, duplicate IDs, Unicode-equivalent IDs and unusual stored priorities. The two apps own their implementations independently; neither app imports the other repository. No persistent cache, schema, hosted service or normal rollout gate changes.

Each owner passes nine new cases plus its existing row-gesture and date-grouping checks: iOS 23 tests, Mac 32, zero failures. Cases cover parity, repeated destinations, each context component independently, private/unreadable replacement, changed source/date/completion/order, missing/reappearing rows, explicit clear and travel. Debug (-Onone) derived targeting for 121 rows and 24 updates falls from about 0.72 seconds to 0.03 seconds, including the new read's initial preparation. This measures that calculation, not total rendering, optimized-release speed or physical FPS.

The signed current-source iPhone Simulator journey performs an actual overdue-to-Today drag, verifies the saved date and fields, executes real history Undo, switches Today/Upcoming four times, then performs another real drag and Undo. Each gesture's counters prove repeated targets reuse one source read; the second gesture starts fresh after navigation. The saved task table returns exactly to baseline after each Undo. No app runtime warnings. These four synthetic tasks do not establish large-library smoothness. The first core run correctly rejected a UTC/GMT test-context mismatch; the fixture was canonicalized. Expanded native attempts first failed at UIKit menu automation; its actual hierarchy exposes Undo by label without the custom identifier. The final selector supports that observed label and retains all saved-state/counter assertions. Concise failure and final logs are retained.
