# Large durable saves · 7 November 2026

A large task edit previously encoded every unchanged field again, including inline legacy attachments on the task being edited. The app's durable-envelope writer now reuses independently validated bytes for byte-exact unchanged fields. It rebuilds current metadata, current table/row order and every field; the on-disk Snapshot format is unchanged. It still reads the real file before saving, writes atomically, and reports success only after that write. Prepared whole-snapshot encodings retain their existing exact-byte fast path.

Admission starts at 512 KiB and stops at the existing 16 MiB envelope budget. Large plain workspaces above 8,192 fields keep the ordinary encoder after optimized measurements showed little warm benefit and a cold penalty; nested preserved table values still qualify. A conservative current-key/entry charge and 50,000-field ceiling avoid selecting a cache that cannot retain the workspace. Uncacheable identities/names, oversized metadata and unsupported optimized encoding use the ordinary writer. Retained encoded values/keys/entry charges have a 16 MiB budget; the per-call UTF-8-exact field-name memo has a separate 64 KiB/512-name ceiling. Cache limits never omit saved fields. File replacement, corrupt input, workspace clear and failed-write readback discard stale memo state.
