# Ordered query sections

Both independent native apps accept comma-separated top-level queries, such as `overdue, today` or `assigned, assigned to:others`. Each query appears as a separate list or board column, in expression order. A task may appear in each query it matches. Bulk selection/actions and the private widget projection use unique task identities. Sorting applies inside each query; optional project/priority/planned-date/deadline grouping subdivides each query. Empty queries remain visible with explicit “No matching tasks” feedback. Accessibility-size board columns widen to keep ordinary words readable. Assignment headings show states or available collaborator display names; unavailable identities show explicit feedback. Heading names are presentation only; stable saved identities and canonical expressions never retarget.

Commas inside quoted search terms, names or date values stay literal. Boolean operators and parentheses retain their precedence within a query. Empty/trailing queries, commas inside parentheses, nested section documents and more than 20 queries reject Save. Separate lists require expression editing; reopening them keeps expression mode rather than flattening the document into a visual AND/OR builder. The preview counts unique matching tasks, not repeated rows.

The account-owned version-1 document retains its envelope and uses a root `sections` operator with 2–20 ordered child rules. Sections may occur only at the root. Unknown older clients must preserve the unsupported document and disable editing; preservation minimum baselines remain iOS `c8d96f8` and Mac `362b3ad`. Both clients need this new evaluator to edit/render these queries. No schema or policy change is required. This does not add unsupported predicates, project hierarchy, filter import or other remaining grammar.

Completion visibility is evaluated per query: an explicit Completed query does not expose completed tasks in an ordinary Assigned/All query. The Include completed setting applies to every query. Missing viewer identity still fails closed in Me/Others expressions; an independent query can remain safe to evaluate. Unavailable exact project/section/label references still produce the saved-view validation error rather than silently rewriting the filter.

Capture uses only explicit metadata shared by every query. Different planned dates or priorities do not invent a default; assignment selection never invents a recipient. Query-specific capture controls are not added. Completion changes the underlying task once and updates every matching list.

Manual order keys identify canonical query content and repeated-query occurrence. Reordering queries and renaming exact targets retain each query’s identity; editing its criteria starts a new order scope. Portable restore remaps project/person references and the matching query order keys, including project subgroups and Inbox’s `project:none` sentinel. Task IDs in these orders remap to restored tasks. Account-cache and offline mutation encoding retain query order and complete documents.

Widgets retain their existing flat task presentation and selected-view ranking, rather than showing all query sections in the widget. Their eight civil-day memberships contain each matching open task once and exclude completed tasks. The payload does not export query expressions, ASTs or collaborator directories. App links open the complete native view with its separate lists.

Each independently owned Core suite passes 518 tests with four existing optional integration skips and zero failures. Each actual-role SQL fixture passes and rolls back to zero fixture users/views. Own unsigned Debug and Release app/widget/test-target compilation passes; Mac Release contains x86_64 and arm64. All eight final isolated iOS 26.5 Simulator flows pass across iPhone 17 Pro and iPad Pro 11-inch (M5), including light/dark Accessibility XXXL assignment regressions, invalid trailing-query rejection, ordered/empty lists, overlapping board completion and persistence after relaunch. Twelve unmodified final query captures are inspected and retained in `query-sections/final/`. The primary expression precedes its short help row; accessibility boards widen. Ordinary scrolling and partial viewports remain necessary, long navigation titles truncate, and long expression/search terms can wrap within words at the largest phone size. Scoped results are in `query-sections-evidence.json`; final owned input hashes are in `query-sections-inputs-sha256.json`. Real paired native online/offline/restore, Mac GUI runtime, VoiceOver/full-surface and physical/provisioned widget-host acceptance remain open. Full P0 remains in progress.
