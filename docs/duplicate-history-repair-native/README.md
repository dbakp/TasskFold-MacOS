# Native acceptance of explicit history custody

The native repair journey exercises the production review, durable draft, command, recovery and original-export controls inside the reserved test application. It selects which duplicate keeps prior activity, reads the retained-event/completion-event counts, undoes the choice, selects it again, closes the app, restores the saved choice, saves the repair, and checks the confirmed result after another cold launch.

A namespace-restricted, file-backed peer supplies a completed original item and a separate open item sharing its old reference. Its history comes from the actual client ledger capture: creation, completion, and the explicit coverage gap caused by the duplicate. The peer supports the explicit positional keeper and binds its event set into its synthetic preview proof. This peer is a UI fixture; SQL authorization, isolation, history custody and rollback are proven separately by the previous owned 332-check suites in each repo.

The UI test covers the actual repair controls and restored confirmation. `Scripts/verify_duplicate_history_native.py` then reads the persisted peer independently: exactly one applied write and receipt, a fresh open identity with no copied history, unchanged keeper completion/version/date, all original events including the gap retained exactly, and an archived original whose byte digest and complete duplicate source agree with the saved receipt. This avoids treating test-only diagnostic text as authoritative storage evidence.

Earlier unsuccessful visibility/diagnostic assertions are documented in `retake.json`; they are not accepted phases.

The phone uses normal text and the iPad uses the largest accessibility text. Both use the test harness's dark appearance. These are native-control, layout and persistence checks; they do not claim a human VoiceOver listening check, hosted delivery or distribution acceptance.

Both owned devices return to Shutdown. Generated unit-test caches and superseded test results are pruned after retaining concise evidence; no new simulators or real task data are used.

## Large-text action layout

The first complete largest-text run exposed overlapping icons/title text in the implicit system-image Save and Export buttons. The production view now uses an explicit intrinsic-width symbol and a wrapping, expanding text column for all three repair Save/Export actions. The symbol is decorative for accessibility, and each action retains its existing text, identifier, enabled-state rules and callback. The final native retakes cover the corrected rows; the before-layout capture is retained separately.
