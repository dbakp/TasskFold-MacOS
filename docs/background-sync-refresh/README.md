# Background sync-refresh preparation

The final workspace read now merges captured rows, prepares widget completion state and encodes the full snapshot on one awaited background worker. Editing can continue while that work runs. The result is accepted only for the exact account/workspace generation, authentication session, editable snapshot revision, presentation/access revisions and review state that created it. An intervening edit (including edit followed by Undo), sign-out or access change cannot be overwritten. Stale results request one coalesced fresh sync after 250 ms; they do not replay the old read or mark that refresh successful. Account changes cancel the scheduled retry.

Access removal still masks immediately and saves its durable fence and encrypted recovery copy before culling. Recovery awaits also prove the captured context. Pending local overlays, review drafts, team filtering and legacy semantics remain. A failed durable save restores the captured in-memory snapshot, including the legacy path.

The mutable widget hash cache remains caller-confined. Workers receive only a bounded immutable seed of opaque record-source proofs and computed hashes, scoped to workspace/session/access. Each worker creates its own cache; it never trusts or retains action tokens. Canonical child/context/state checks still run. The existing private prepared-encoding attestation remains the only way to skip duplicate widget preparation. Final saving still rereads/stages the durable ledgers and proves exact buffers/metadata before reusing bytes; any mismatch falls back to ordinary encoding. Atomic disk writes and widget publication stay behind the existing guards.
