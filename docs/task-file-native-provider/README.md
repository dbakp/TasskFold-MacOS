# Native file publication against the real local provider

Reviewed 2 November 2026. This is an isolated native acceptance workflow, not ordinary-use enablement or hosted deployment. Verification records actual results; a successful build or a published backend row alone is not accepted as the complete native flow.

Both app sources include an exact-host DEBUG transport bridge. It accepts an explicit test flag, fixed synthetic account and a loopback-only origin. The app receives only a disposable user token, never the service-role key. The production Backend, upload journal and recovery controls perform the client actions; actual HTTP handlers, SQL sessions/access checks and pinned Storage API perform the local service work. Auth/RPC HTTP routing remains a minimal fixture, not genuine hosted Auth or OAuth. Redirects, cookies, response size and request paths are bounded; no normal app transport policy is relaxed.

The native cases prepare a generated private original, share it through the file sheet, receive an intentionally lost/interrupted final response, close and cold-reopen through Saved file upload, then Check status or Stop. A genuine terminal receipt must survive another cold return before explicit clearing. The owning driver independently verifies one server operation, one provider POST, exact bytes or cancellation, task attachment count and cleanup/quota behavior. This is not full ordinary task synchronization, since the existing isolated task fixture keeps broad sync paused. Local task rows and pending edits must remain unchanged; actual server attachments are verified separately.

A shared owning-repo setup module now initializes the real Storage schema and unchanged migration dependencies for both direct-provider and native tests. It preserves each repository's own migration filenames. Earlier native failures and the captured real wire are retained as diagnostics; no failed native case is treated as acceptance. The native backend reply also has a focused cold-decoding regression in each Core suite.

No real user tasks, passwords, hosted accounts, persistent Docker volumes or existing containers are touched. The driver restores the two reserved Simulators to their original state, closes the app and removes disposable configuration after inspecting the current installed container identity. Failed test-only originals from disposed backend fixtures are preserved as encrypted files before an explicitly scoped fixture reset; this is not a product recovery-clear path. User rollout/provider/device deferrals remain unchanged.

The test address is canonicalized with an explicit `/` before query parameters. An empty root path was normalized by URLSession and correctly failed the bridge’s strict response-URL match; that harness failure is recorded, and the production URL guard was preserved. The bridge keeps a bounded, token-free audit of test reply/error phases for diagnosis, removed with its disposable user configuration.
